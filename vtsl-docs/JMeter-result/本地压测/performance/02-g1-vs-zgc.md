# G1 vs 分代 ZGC

> 环境: 8vCPU/16GB VM | Redis + MySQL + Kafka + Nacos 跨网络 | Seckill 单服务
> 数据来源：`../raw-data/g1/`, `../raw-data/zgc/`

---

## 摘要

同口径压测（450 并发 / 45s / 10w 订单），G1 因 Evacuation Pause（STW）产生 **856ms GC 总耗时**；ZGC 全部并发执行，GC 总耗时仅 **3ms**，应用线程零阻塞。

应用层（300 并发 / 30s）ZGC 相比 G1 的收益：
- TPS **+10.2%**（1191 → 1312）
- P99 **↓32%**（269ms → 183ms）
- Max **↓26%**（385ms → 286ms）

---

## GC 层对比（450 并发 / 45s）

| 指标 | G1 | ZGC | G1 是 ZGC 的倍数 |
|------|:---:|:---:|:-----------:|
| **YGCT（Young GC 总耗时）** | **0.652s** | **0.001s** | **652x** |
| **CGCT（并发 GC 总耗时）** | **0.205s** | **0.001s** | **205x** |
| **GC 总耗时** | **0.856s** | **0.003s** | **285x** |
| Young GC 次数 | 170 次 | 9 次 | 19x |
| Full GC | 0 | 0 | - |
| GC 触发原因 | G1 Evacuation Pause（STW） | Proactive / High Usage（并发） | - |
| **应用线程阻塞** | ✅ 每次 YGC 均 STW | ❌ 零阻塞 | - |

> G1 所有 Evacuation Pause 均为 STW 操作；ZGC 的 GC 全部并发执行。

## 拐点分析

| 并发 | TPS 甜点 | P99 |
|:---:|:--------:|:---:|
| 300 | ✅ 1,312 (ZGC phase5) | 183ms |
| 350 ~ 400 | 1,289 ~ 1,342 | 238 ~ 242ms |
| 450 | 1,281 ~ 1,299 | 309 ~ 371ms |

- **300 并发为性能甜点**：资源利用最优
- **400 并发接近天花板**：TPS 基本持平，延迟开始恶化
- **450 并发进入过载区**：服务容量边界

## 结论

ZGC 彻底消除 GC STW 抖动对 P99 的影响，是秒杀场景 GC 选型的决定性优势。
