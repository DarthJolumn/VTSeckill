## 1. Region 化堆内存（✅）

- 堆划分为 ~2048 个等大 Region，四角色动态切换：Eden / Survivor / Old / Humongous（无固定物理分代比例）。
- **Region Size = Heap/2048 向上取整到最近 2 的幂**（1MB~32MB）。必须是 2 的幂：G1 内部用位运算定位 Region 索引。
- **上限 32MB 钳制**：堆 ≥64GB 时按 32MB 算，Region 数量降到 512~2048 区间内（下限 512 个）。
- 手动 `-XX:G1HeapRegionSize` 可突破默认约束（解决 Humongous 问题第一手段）。

## 2. TLAB 分配链路（✅）

```
线程私有 TLAB（top 指针 = 下次写入位置）
  → 指针碰撞：top 指向空闲位置，碰撞成功 → 直接分配
  → TLAB 满 → CAS 抢当前 Region 共享区（非 TLAB 分配）
      → 成功 → 直接分配对象 / 按需划新 TLAB
      → 失败（Region 也满）→ CAS 竞争 FreeList 取新 Eden Region → 初始化新 TLAB
```

- TLAB 是 Region 内部子区间，一个 Region 可容纳多线程 TLAB + 共享区；TLAB 耗尽 ≠ Region 耗尽。
- **虚拟线程不持有 TLAB**，复用挂载的载体线程（Platform Thread/JavaThread）的 TLAB——切换零额外开销。

## 3. Card Table（✅）

- **全局 byte 数组**（不是 Region 级）：堆按 512B 划分为 Card，`Card_Index = (地址 - HeapBase) >> 9`；每 Card 对应 1 byte（不是 bit）。
- **标脏条件**：发生**跨 Region 引用赋值**才标脏（G1 无"跨代"概念，只有"跨 Region"）；同 Region 内引用赋值不标脏。
- **byte 多状态机**（STW 扫描量转移到并发的关键）：

| 状态 | 含义 |
|---|---|
| Clean | 无跨区引用变更 |
| Dirty | 写屏障检测到跨区引用赋值 |
| Scanned | 本轮 GC 已扫描、RSet 已更新（防重复扫描） |
| Precleaned | 并发预清理已处理，STW 时验证后跳过（握手协议） |

## 4. RSet（✅）

- **定义**：Region 级、记录**外部入站引用**（外部 → 本 Region），GC 回收本 Region 时无需全堆扫描。
- **精确粒度**：记录 **源对象地址 + 字段偏移量**（不是笼统的"哪个 Region 引用我"）——GC 直接读 (addr, offset) 定位指针，O(1)。
- 只记单向入站：本 Region 内部互引不记、出站引用由对方 Region 的 RSet 负责。
- **三级存储**（按引用密度动态选择）：SparsePRT（≤4 条，数组）→ HashTable → Coarse Bitmap（粗粒度位图，牺牲精度换空间）。

## 5. 写屏障（✅）

- **主路径（99%）**：Post-Write Barrier 在引用赋值时直接写 RSet（`is_reference && 跨Region && 目标 Region 需要`）。
- **Card Table 是兜底安全网（1%）**，处理写屏障覆盖不了的三类场景：JNI/Unsafe 直接内存写入、写屏障被禁用的批量操作、并发标记阶段 RSet 更新异常。
- 兜底路径：GC 扫描 Dirty Card → 借助 OopMap（Klass → 引用字段偏移表）反查精确引用 → 补入 RSet。
- **SATB ≠ Card Table**：SATB 保证并发标记"不漏标"（记录被覆盖旧值），Card Table 保证"RSet 不缺"，职责分离互不替代。

## 6. CSet + G1YoungList（✅）

- **CSet = 本次 GC 要回收的 Region 集合（不是对象集合）**。
  - Young GC：所有 Eden + Survivor Region（**无条件全收**）。
  - Mixed GC：所有 Young + 按垃圾比例/效率排序选出的部分 Old。
  - Full GC：整个堆。
- **G1YoungList 链表**：专门记录所有 Eden Region + 存活 Survivor Region，触发 GC 直接遍历链表拿到 Young Region，不用扫全堆。
- Young GC 可达性：**不扫描 Old 区本身**，只扫描 Young Region 的 RSet（Old→Young 引用作为额外 GC Roots）——耗时与 Old 区大小解耦，这是可预测停顿的基础。

## 7. Bitmap（✅）

- **职责**：标记对象**存活状态**（Mark Bitmap 标记阶段 / Live Bitmap 复制阶段，同一结构两个叫法）；**不是标脏**——标脏是 Card Table 的专属职责（CMS 的 Mod Union Table 才是 Bitmap 记脏卡，G1 已不用）。
- **地址映射**：对象按 8 字节对齐 → `对象地址 / 8 = 位图索引` → O(1) 定位置位。
- 写屏障 → Card Table（标脏）→ RSet → CSet（时间预算选择）→ Mark Bitmap（标记存活）→ 复制/回收。

## 8. 可预测停顿时间模型（👀 刚看，需复述）

**本质：带时间预算的贪心算法。**

- 输入：`MaxGCPauseMillis`（默认 200ms，软实时目标）+ 历史 GC 统计（单 Region 平均处理耗时）+ Region 垃圾比例。
- CSet 构建：**事前预测**——每加一个 Old Region 前先预测总耗时，预测超预算 → 立即停止（不是"加了再退"）。
  - ① Young Region 无条件全加入；② Old Region 按回收效率 = 垃圾字节数 / (复制成本 + RSet 扫描成本) 从高到低；③ 预测超标停止。
- 自适应：上一轮实际超标 → 调低处理速度估算 → 下一轮 CSet 自动缩小。
- 时间优先于完整性：宁可多轮 Mixed GC 慢慢清，不单次停顿超标。

## 9. 三大 GC 完整流程（8/20 补全）

### 9.1 Young GC（✅）

- **触发**：Eden Region 填满（TLAB + 共享区 CAS 均失败）。
- **流程**：STW → 扫 GC Roots + 各 Region RSet（Old→Young 引用作额外 roots）→ **Mark-Copy 复制算法**（BFS 队列遍历：取出对象→扫引用→未复制先复制→入队，复制与待扫描并行）→ 存活对象复制到新 Survivor（或晋升 Old）→ 清空原 Eden/Survivor → 更新引用。
- **Bitmap 不参与 Young GC 标记**：Young GC 是复制型回收，存活判断靠"从 roots 可达即复制"，不需要位图。
- **晋升规则**：Survivor 满或年龄达标 → 晋升 Old。

### 9.2 并发标记周期四子阶段（✅）

- **触发**：老年代占用 ≥ IHOP（默认 45%），与 Mixed GC 是上下游关系（标记完才有 Mixed GC）。
- **初始标记（STW）**：**依附于 Young GC 执行**——先做 Young GC 复制，再标记存活对象到 Bitmap。
- **并发标记**：从 Bitmap 起点遍历对象图，**SATB（前写屏障）记录并发期间被覆盖的旧引用**，防漏标。
- **最终标记（STW）**：处理 SATB 队列残留，修正漏标。
- **清理/统计（STW）**：计算各 Old Region 存活字节数 & RSet 大小 → 排序。
- 只"记账"不回收；分配速率 > 标记速率 → Concurrent Mode Failure → Full GC。

### 9.3 Mixed GC 触发链路（✅）

```
IHOP 45% 触发并发标记周期（JDK 8~10 阶段演进：并发标记 → CSet 构建 → Mixed 执行）
→ CSet 构建：G1YoungList 拿全部 Young + Old 按回收效率（垃圾字节/(复制成本+RSet 扫描)）排序 + 事前预测
→ Mixed GC 执行（多轮 STW）：扫 roots+RSet → 复制存活 → 更新引用 → 清空归还 FreeList
→ 终止：垃圾 < G1HeapWastePercent(5%) 或达 G1MixedGCCountTarget(8) 或 Old 全回收
```

### 9.4 Full GC（✅，8/20 重点）

**触发条件（用户口述）**：大对象（Humongous）分配不下、FreeList 无可用 Region、Metaspace 不足、Mixed 来不及、System.gc() 等。

**与 Mixed GC 是两套完全不同的机制**：

| 维度 | Mixed GC | Full GC |
|---|---|---|
| 算法 | **Mark-Copy**（复制转移） | **Mark-Compact**（滑动压缩，不需要额外目标空间） |
| 范围 | CSet 中的 Region（部分堆） | 整个堆 |
| STW | 仅部分阶段 | **全程 STW，无并发** |
| Bitmap | ✅ 依赖并发标记结果 | ❌ 自己重新标记（标记可能未完成/已过期） |
| CSet | ✅ 核心驱动 | ❌ 不使用（无可信 CSet） |
| RSet | ✅ 定位跨区引用 | ⚠️ 可选复用，不可用则全堆指针扫描 |
| 碎片 | Region 级，可能残留 | 全堆紧凑，彻底消除 |

**执行过程**：根扫描 → 标记压缩（标记存活 + 计算新地址）→ 移动对象（**滑动压缩**，不是复制）→ 更新引用 → 重置元数据（清空 Region 状态、重建 FreeList、重置 Bitmap/RSet）。

**⚠️ 版本分水岭（面试重点）**：**JDK 8/9 Full GC 单线程 Serial Old**（64GB 堆停顿可达几十秒，生产事故根源）→ **JDK 10+（JEP 307）改多线程 Parallel Old**。用 JDK 8 跑 G1，避免 Full GC 优先级高一个数量级。

**Metaspace 细节**：正常 GC 无法清空 Metaspace（需触发 Metaspace GC/FGC 场景）。

### 9.5 IHOP / 自适应 IHOP（🟡）

- **IHOP 本质**：在"标记完成时刻"和"堆满时刻"之间找时间差。设太低 → 标记太早完成，Bitmap 过期要重标；设太高（85%）→ 缓冲空间不足，并发标记没跑完堆就满 → Concurrent Mode Failure。
- **最佳 ≈ 100% - (并发标记耗时 × 分配速率) / 堆总大小**：分配快标记慢 → 必须设低（35-45%）；极快 → 25-30% 甚至换 ZGC。
- **JDK 10+ Adaptive IHOP**：根据历史标记耗时/分配速率自动动态调整（JDK 8/9 无自适应，需手动）。
