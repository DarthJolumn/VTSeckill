## 三、PostgreSQL vs MySQL 精通总结

### 3.1 存储架构对比（已掌握）

| 维度 | PostgreSQL | MySQL (InnoDB) |
|------|-----------|----------------|
| **数据组织** | 堆表（Heap Table），无序存储 | 聚簇索引，按主键物理有序 |
| **索引结构** | B-Tree，索引与数据分离 | B+Tree，索引即数据 |
| **主键查询** | 索引→TID→回表（2次IO） | 直达数据（1次IO） |
| **二级索引** | 与主键索引结构相同，存TID | 存主键值，需回表 |
| **写入方式** | 追加到堆表末尾 | 聚簇索引中定位插入 |

**你的核心理解**："PG堆和表是表，索引是索引，两个通过地址关联"

### 3.2 MVCC实现对比（已掌握）

| 维度 | PostgreSQL | MySQL |
|------|-----------|-------|
| **版本存储** | 新旧版本共存堆表 | Undo Log独立存储 |
| **版本链** | t_ctid指针（堆内） | roll_pointer（Undo Log） |
| **事务ID** | XID 32位循环使用 | 事务ID 64位递增 |
| **可见性判断** | Snapshot + CLOG | ReadView + 隐藏字段 |
| **空间回收** | VACUUM清理dead tuple | Purge线程清理Undo |

**你的核心理解**："PG UPDATE = 堆表追加新版本，MySQL = 原地修改 + Undo Log"

### 3.3 事务隔离级别（已掌握）

| 级别 | PostgreSQL | MySQL | 差异说明 |
|------|-----------|-------|----------|
| **RC** | 语句级Snapshot | 语句级ReadView | ✅ 等价 |
| **RR** | 事务级Snapshot | 首次读ReadView | PG更严格，MySQL有幻读 |
| **Serializable** | SSI乐观检测 | 2PL悲观锁 | 实现哲学完全不同 |

**你的核心理解**："PG RC和MySQL RC等价，都是语句级；PG RR是事务级Snapshot，天然避免幻读"

### 3.4 写偏斜问题（已掌握）

- **定义**：两个事务读取对方要修改的数据，基于旧值做出合法写入，破坏业务约束
- **解决**：仅Serializable可解，PG用SSI检测危险结构，MySQL用2PL串行执行

**你的核心理解**："写偏斜就是双方用对方的旧数据去写，只有串行化能解决"

### 3.5 特色机制（已掌握）

| 机制 | 你的理解 | 关键点 |
|------|----------|--------|
| **JSONB+GIN** | "路径值→行号列表，倒排索引" | 适合包含查询，B-Tree适合等值/范围 |
| **VACUUM** | "解决表膨胀、查询退化、XID回卷、统计信息过期" | 必须定期执行，否则性能劣化 |
| **Visibility Map** | "标记页是否全可见，Index-Only Scan优化" | VACUUM维护，非实时更新 |

### 4.1 IOC容器（已掌握）

**你的理解**："控制反转，对象创建和生命周期交由容器管理"

### 4.2 Bean生命周期（已掌握）

```
实例化 → 属性填充 → 初始化 → 注册销毁回调
    ↓         ↓         ↓           ↓
  反射创建   依赖注入   BPP Before  销毁方法
  三级缓存   解决循环   初始化方法
             依赖      BPP After
```

**你的核心理解**："doCreateBean四步：实例化、属性填充、初始化、注册销毁"

### 4.3 三级缓存解决循环依赖（已掌握）

| 缓存 | 内容 | 作用 |
|------|------|------|
| 一级 | 完整Bean | 最终可用对象 |
| 二级 | 早期引用（未初始化） | 暴露半成品 |
| 三级 | ObjectFactory | 生成早期引用（含代理） |

**你的核心理解**："二级缓存解决不了代理类前后引用不一致，需要三级缓存的ObjectFactory"

### 4.4 依赖注入链路（已掌握）

```
@Autowired/@Resource/@Value

AutowiredAnnotationBeanPostProcessor（扫描）
    ↓
InjectionMetadataCache（缓存元数据）
    ↓
populateBean（属性填充）
    ↓
反射赋值
```

**你的核心理解**："先扫描注解存入InjectionMetadataCache，再从缓存取依赖注入"

## 五、ZGC与分代ZGC 熟练总结

### 5.1 染色指针（已掌握）

| 状态 | 含义 | 转换时机 |
|------|------|----------|
| **Remap** | 引用已更新 | 自愈完成 |
| **Mark0** | 本轮标记存活 | 并发标记开始 |
| **Mark1** | 上轮标记存活 | 新一轮标记 |
| **Finalizer** | 待 finalize | 标记阶段发现 |

**你的核心理解**："染色指针记录引用状态，读屏障检查并触发自愈"

### 5.2 读屏障自愈（已掌握）

```
读取引用 → 检查染色指针
    ↓
Remap? → 直接访问
    ↓
Mark0/1? → 查转发表 → 更新为新地址 → 染色Remap → 返回新地址
```

**你的核心理解**："读到旧指针→查映射表→更新引用→染色Mark"

### 5.3 分代ZGC改进（已掌握）

| 改进点 | 说明 |
|--------|------|
| **分代标记** | 染色指针多1bit区分Young/Old |
| **独立GC** | Young GC和Old GC可并发执行 |
| **RSet优化** | 应用线程本地buffer→批量刷入Dynamic RSet |
| **单向引用** | 严格Young→Old引用，保证可并发 |

**你的核心理解**："非分代每次遍历整个堆做无用功，分代后Young/Old独立管理"

### 5.4 关键疑问解答（已掌握）

- **转发表保留**："对象清除后，转发表保留到下次GC，保证自愈"
- **GC Roots扫描**："STW只扫第一跳引用，存入Root Set，时间短"
- **Young/Old并发**："两套染色指针，严格单向引用，互不阻塞"

Buffer Pool
├── trunk → 控制块数组 → frame（页）

### 6.4 MVCC三大基石（已掌握）

## 九、面试话术储备

### 9.1 数据库对比类

**Q: PG和MySQL有什么区别？**

> "从存储架构看，PG用堆表+独立索引，MySQL用聚簇索引。这导致主键查询MySQL更快（1次IO），但PG写入更友好（无需页分裂）。
>
> MVCC实现上，PG新旧版本共存堆表，MySQL用Undo Log。PG需要VACUUM回收空间，MySQL自动Purge。
>
> 隔离级别上，RC两者等价，RR差异大：PG是事务级Snapshot天然避免幻读，MySQL需Next-Key Lock。"

### 9.2 Spring机制类

**Q: Spring如何解决循环依赖？**

> "三级缓存：一级存完整Bean，二级存早期引用，三级存ObjectFactory。
>
> A创建时需要B，B创建时需要A。A先放入三级缓存，B从三级缓存获取A的早期引用（可能代理），B完成后放入一级，A再注入完整的B。
>
> 关键点是三级缓存的ObjectFactory在getEarlyBeanReference时决定是否生成代理，解决前后引用不一致。"

### 9.3 JVM GC类

**Q: ZGC为什么能做到亚毫秒停顿？**

> "三大支柱：染色指针、读屏障、Region化内存。
>
> 染色指针在引用上记录状态（Remap/Mark0/Mark1），读屏障检查状态并触发自愈，对象转移时只需更新转发表，应用线程访问旧地址时自动跳转到新地址。
>
> 分代ZGC进一步优化：Young/Old独立GC，染色指针多1bit分代标记，RSet记录跨代引用，严格单向引用保证Young/Old GC可并发。"
