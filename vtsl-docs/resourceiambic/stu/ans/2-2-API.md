### 接入校验与缓存设计

#### 🎯 核心亮点
-   **网关前置正则拦截**：Base62 格式校验在缓存之前执行，无效短码零成本拦截，不穿透缓存和 DB
-   **二级缓存分层设计**：Caffeine L1（3s）挡热点 + Redis L2（24h）挡全量，命中率叠加，DB 压力趋近于零
-   **缓存值携带 urlId 免回查**：统计埋点直接从缓存对象取 urlId，命中路径零额外 IO，重定向与统计全链路无阻塞

#### 💬 面试话术

> 重定向接口是短链系统里 QPS 最高的入口，所有优化都围绕**减少无效请求穿透**和**缩短命中路径**两个方向。
>
> **第一层是网关前置校验。** 在进缓存之前，先用正则校验 shortKey 是否符合 Base62 格式且长度等于 6。这一步的意义在于：爬虫、暴力枚举、手误输入的请求在正则这一步就被拦掉了，不会穿透到 Caffeine、不会穿透到 Redis、更不会穿透到 MongoDB。相当于在最前面加了一道零成本的布隆过滤器——虽然不如布隆精确，但对于格式明显非法的请求，正则比布隆更快更简单，一行代码就挡住了。
>
> **第二层是二级缓存。** 校验通过后先查 Caffeine 本地缓存，TTL 设 3 秒，专门挡短时间内重复访问同一条短链的热点请求，比如用户连续点击、爬虫短时间内重复抓取。Caffeine miss 了再查 Redis，TTL 设 24 小时，挡全量已创建的短码。Redis miss 了才回查 MongoDB。这样三层递进，正常流量下 DB 的读 QPS 趋近于零。
>
> **为什么 Caffeine 只设 3 秒？** 因为短链一旦创建就不会变，理论上可以设很长。但 3 秒是一个平衡点：太短挡不住热点，太长会导致短链被删除或禁用后本地缓存还返回旧数据，3 秒是"热点拦截"和"一致性收敛"之间的折中。真正的长周期一致性靠 Redis 层保证。
>
> **第三层是缓存值设计。** 缓存里存的不是单纯的 URL 字符串，而是包含 urlId 的完整对象。这样异步统计埋点时直接从缓存对象取 urlId，不需要再拿 shortKey 回查一次 DB 或 Redis 来获取 urlId。重定向路径上每少一次 IO，P99 延迟就少一截。
>
> **统计本身是异步的。** 重定向 302 返回后，通过异步任务记录点击事件、解析 UA 和 GeoIP，不阻塞用户跳转。统计写失败也不影响主链路，最多丢一条埋点，不影响短链可用性。

#### ⚠️ 高频追问预备

-   **"为什么不用布隆过滤器而用正则？"**
    布隆过滤器解决的是"这个 key 存不存在"的问题，适合防缓存穿透。但我们的场景更简单——短码格式是固定的 6 位 Base62，格式非法的请求占比远大于"格式合法但不存在"的请求。正则一行代码、零内存开销、纳秒级判断，性价比远高于布隆。对于"格式合法但不存在"的穿透，靠 Redis 缓存空值兜底即可。

-   **"Caffeine 3 秒会不会太短，命中率不高？"**
    3 秒看起来短，但短链访问有明显的热点效应——一条短链被分享到群里，前几秒会有大量并发访问。3 秒足够挡住这波瞬时热点。长尾访问由 Redis 层承接，Caffeine 的定位就是"最前面挡一波最热的"，不需要它承担全量缓存。

-   **"Redis L2 缓存和 DB 的一致性怎么保证？"**
    短链创建后不会修改，只有删除（逻辑删除）。删除时主动删除 Redis 缓存，Caffeine 靠 3 秒 TTL 自然过期。最坏情况下删除后 3 秒内本地缓存还命中，但这是可接受的——短链删除不是高频操作，3 秒窗口期影响极小。

-   **"缓存穿透怎么防？"**
    格式非法的靠正则拦截；格式合法但不存在的，查 DB 后缓存空值（短 TTL，比如 60 秒），防止同一个不存在的 key 反复穿透。如果恶意构造大量不同的合法格式 key，可以叠加限流（项目里已经有 Redis 固定窗口限流器）。

-   **"为什么统计要异步？同步会有什么问题？"**
    同步统计意味着重定向响应要等 GeoIP 解析、UA 解析、埋点写入全部完成才能返回。GeoIP 查库可能耗时几毫秒到几十毫秒，UA 解析也有开销，这些加在用户跳转路径上直接拉高 P99。异步化后用户感知延迟只有缓存查询 + 302 重定向，统计在后台慢慢做，丢了也不影响业务。

-   **"二级缓存的查询顺序能反吗？先查 Redis 再查 Caffeine？"**
    不能。Caffeine 是本地内存，访问延迟纳秒级；Redis 是网络调用，延迟毫秒级。先查本地再查远程，命中率叠加且总延迟最低。反过来的话每次都要走一次网络，Caffeine 就失去意义了。
