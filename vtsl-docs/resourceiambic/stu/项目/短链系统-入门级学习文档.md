## 一、模块总览与架构图

### 1.1 双服务架构
| 角色 | 模块 | 端口 | 通信 |
|---|---|---|---|
| 发号器 KGS | `vtsl-shortlink-keygenerator` | HTTP 8082 / gRPC 50051 | gRPC 供 API 调 |
| 业务层 API | `vtsl-shortlink-api` | HTTP 8085 | 对外 REST，对内 gRPC 调 KGS |

两者**完全解耦**：API 只管「向 KGS 要一个短码」，不知道短码怎么生成；KGS 只管「产短码 + 发短码」，不知道业务含义。

### 1.2 存储选型分离（简历亮点）
| 存储 | 用途 | 集合/表 |
|---|---|---|
| **MongoDB** | 短码全局库存（唯一性 + 状态机） | `shortkeys` |
| **MySQL** | 业务映射（归属、原标题、点击数、统计） | `t_url` / `t_analytics` |
| **Redis** | 短码发放队列（List）+ L2 缓存 + 限流计数 | `shortly-kgs-redis-queue` / `url:*` / `rate_limit:*` |

## 二、存储模型（先认表/集合）

### 2.1 Mongo `shortkeys`（短码库存）
`ShortKeyDocument.java`：
```java
@Document(collection = "shortkeys")
public class ShortKeyDocument {
    @Id private String id;
    @Indexed(unique = true) private String key;   // 短码，全局唯一
    private String status;                         // "available" / "used"
    @Field("createdAt") private Instant createdAt;
}
```
- `key` 上 `@Indexed(unique=true)` 是**唯一性最后一道防线**。
- `status` 状态机：`available` ↔ `used`，靠 CAS 推进。

### 2.2 MySQL `t_url`（业务映射）
`Url.java`：`@Table(name="t_url")`
- `id` 自增（业务主键，analytics 关联它）
- `short_key` `unique` 长度 50 —— 业务层也兜底唯一
- `original_url` TEXT、`title`、`user_id`、`clicks`（点击数）、`created_at`/`updated_at`/`deleted_at`（软删除）
- 软删除：所有查询带 `deletedAtIsNull`，删除只是填 `deleted_at`

### 2.3 MySQL `t_analytics`（点击统计）
`Analytics.java`：`@Table(name="t_analytics")`
- `url_id` 关联 `t_url.id`、`clicked_at`、`ip_address`、`user_agent`(TEXT)、`referrer`
- 解析维度：`country`(GeoIP)、`device`/`browser`/`os`(UA 解析)

**学习要点**
- 短码字符串是「解耦键」：Mongo 管唯一、MySQL 管归属，两套存储独立演进互不阻塞。
- 为什么短码不落 MySQL 业务表当主键？因为短码生命周期（库存/发放）在 Mongo，业务只需持有字符串引用。

## 三、KGS 发号器详解（简历核心）

### 3.1 常量集中地
`KgsConstants.java`：
```java
public final class KgsConstants {
    public static final String REDIS_QUEUE_NAME = "shortly-kgs-redis-queue";
    public static final long QUEUE_THRESHOLD = 200;     // 队列低于此值触发补货
    public static final int BATCH_SIZE = 1000;           // 每次补货 1000 个
    public static final int KEY_LENGTH = 6;              // 短码 6 位
    public static final int MAX_GENERATE_ATTEMPTS = 3;   // 生成批次重试上限
    public static final int MAX_ISSUE_ATTEMPTS = 3;      // 单次发放取号重试上限
    public static final String STATUS_AVAILABLE = "available";
    public static final String STATUS_USED = "used";
}
```

### 3.2 随机码生成（Base62）
`Base62Util.java`：
```java
public static String randomKey(int length) {
    BigInteger max = BASE.pow(length);                              // 62^6 ≈ 568 亿
    BigInteger n = new BigInteger(max.bitLength(), RANDOM).mod(max);// SecureRandom
    StringBuilder sb = new StringBuilder();
    while (n.compareTo(BigInteger.ZERO) > 0) {
        BigInteger[] div = n.divideAndRemainder(BASE);
        sb.append(CHARSET.charAt(div[1].intValue()));
        n = div[0];
    }
    while (sb.length() < length) sb.append(CHARSET.charAt(0));      // 前补 0 字符
    return sb.reverse().toString();
}
```
- 字符集 62 个（`0-9a-zA-Z`），`SecureRandom` 保证不可预测 → **随机码防枚举**。
- 6 位空间 ≈ 62^6 ≈ 5.68×10^10（568 亿）。

### 3.3 预生成（库存灌队）
`KeyGenerator.generateBatch()`：
```java
public void generateBatch(int count) {
    for (int attempt = 0; attempt < KgsConstants.MAX_GENERATE_ATTEMPTS; attempt++) {
        List<String> keys = new ArrayList<>(count);
        List<ShortKeyDocument> docs = new ArrayList<>(count);
        for (int i = 0; i < count; i++) {
            String key = Base62Util.randomKey(KgsConstants.KEY_LENGTH);
            keys.add(key);
            docs.add(new ShortKeyDocument(key, KgsConstants.STATUS_AVAILABLE, Instant.now()));
        }
        try {
            mongoTemplate.insert(docs, "shortkeys");                       // ① 落库 available
            redisTemplate.opsForList().leftPushAll(REDIS_QUEUE_NAME,
                keys.toArray(new String[0]));                              // ② 入队
            return;
        } catch (DuplicateKeyException e) {                                // 撞唯一索引 → 整批重试
            log.warn("Duplicate keys in batch, retrying ...");
        }
    }
    throw new RuntimeException("Failed to generate keys ...");
}
```
> ⚠️ **顺序隐患（面试深挖点）**：先 Mongo 后 Redis。若 ① 成功、② Redis 故障，这批码永久 `available` 却不在队列 → 成为「孤儿库存」（不破坏唯一性，但泄漏）。建议改为「先入队成功再标 Mongo 可用」或加补偿扫描。

### 3.4 发放（最关键）
`KeyService.getKey()`：
```java
public String getKey() {
    for (int attempt = 0; attempt < KgsConstants.MAX_ISSUE_ATTEMPTS; attempt++) {
        Long queueLen = redisTemplate.opsForList().size(REDIS_QUEUE_NAME);
        if (queueLen == null) throw new RuntimeException("Redis unavailable");
        if (queueLen < KgsConstants.QUEUE_THRESHOLD) {
            keyGenerator.generateBatch(KgsConstants.BATCH_SIZE);          // 阈值触发补货
        }
        String key = redisTemplate.opsForList().rightPop(REDIS_QUEUE_NAME);// RPOP O(1) 无竞争
        if (key == null) { log.warn("Queue empty ..."); continue; }

        var result = mongoTemplate.updateFirst(                           // Mongo CAS 双保险
            Query.query(Criteria.where("key").is(key).and("status").is(STATUS_AVAILABLE)),
            Update.update("status", STATUS_USED), "shortkeys");
        if (result.getModifiedCount() > 0) return key;                    // CAS 成功才发
        log.warn("CAS failed for key {}, discarded ...");                 // 脏 key 丢弃不回队
    }
    throw new RuntimeException("Failed to issue key ...");
}
```
**为什么这样设计**
- `RPOP` 是 O(1)、无锁、多实例不竞争（Redis 单线程保证原子）。
- CAS `available→used` 是双保险：即使同一码被重复入队（理论不会），也只有一次 CAS 能成功。
- 脏 key（CAS 失败，说明已是 used）**直接丢弃取下一个**，不回队 → 避免「取出→失败→回队」死循环。
- 队列空/ CAS 一直失败：`MAX_ISSUE_ATTEMPTS=3` 兜底后抛异常，gRPC 转 INTERNAL。

### 3.5 gRPC 服务端
`KeyGrpcService.getKey()`：
```java
@Override
public void getKey(Empty request, StreamObserver<KeyResponse> responseObserver) {
    try {
        String key = keyService.getKey();
        responseObserver.onNext(KeyResponse.newBuilder().setKey(key).build());
        responseObserver.onCompleted();
    } catch (Exception e) {
        responseObserver.onError(
            Status.INTERNAL.withDescription("key generation failed: " + e.getMessage()).asRuntimeException());
    }
}
```
`GrpcServerConfig`（实现 `ApplicationRunner`，端口 50051，`usePlaintext` 明文，无 TLS）：
```java
server = ServerBuilder.forPort(grpcPort).addService(keyGrpcService).build().start();
```
> 说明：KGS 是纯 gRPC + Health 服务，无 Servlet 鉴权需求，故扫描包只含 `vtslkgs` + vtslcommon 的 `exception`/`dto`（`VtslKeyGeneratorApplication.java:12`）。

## 四、API 业务层详解

### 4.1 控制层（7 个接口）
`UrlController.java`，全部前缀 `/api/v1`：
| 方法 | 路径 | 鉴权 | 限流 | 说明 |
|---|---|---|---|---|
| POST | `/url/shorten` | `@RequireAuth` | 5/60s | 创建短链（核心） |
| GET | `/url/` | `@RequireAuth` | 20/60s | 我的短链列表 |
| GET | `/url/{shortKey}` | `@RequireAuth` | 20/60s | 详情 |
| PATCH | `/url/{shortKey}` | `@RequireAuth` | 5/60s | 改短码/标题 |
| DELETE | `/url/{shortKey}` | `@RequireAuth` | 5/60s | 软删除 |
| GET | `/url/redirect/{shortKey}` | `@PublicApi` | 50/60s | 跳转 + 记 analytics |
| GET | `/analytics/{urlId}` | `@RequireAuth` | 10/60s | 点击统计 |

- `requireUserId()` 从 `UserContext.currentUserId()` 取，为 null 抛 401。
- redirect 用 `@PublicApi` → 别人点短链无需登录。

### 4.2 创建短链
`UrlService.create()`：
```java
public CreateUrlResponse create(Long userId, CreateUrlRequest req) {
    if (urlRepository.existsByOriginalUrlAndUserIdAndDeletedAtIsNull(req.getOriginalUrl(), userId))
        throw new BizException(409, "This URL has already been shortened.");   // 防同用户重复

    String shortKey = req.getShortKey();
    if (shortKey == null || shortKey.isBlank()) {
        try { shortKey = keyServiceClient.getKey(); }                            // 向 KGS 要号
        catch (Exception e) { throw new BizException(500, "Failed to generate short key"); }
    }
    if (urlRepository.existsByShortKeyAndDeletedAtIsNull(shortKey))
        throw new BizException(409, "The generated ShortKey already exists, please try again");

    Url url = new Url();
    url.setOriginalUrl(req.getOriginalUrl());
    url.setShortKey(shortKey); url.setTitle(req.getTitle()); url.setUserId(userId);
    urlRepository.save(url);                       // MySQL 落库（short_key unique 兜底）
    cacheUrlAsync(url);                            // 写二级缓存
    return CreateUrlResponse.from(url);
}
```
**学习要点**
- 用户自定义 shortKey 也走 `existsByShortKey` 校验；KGS 生成的短码基本不撞（568 亿空间 + Mongo 唯一索引）。
- KGS gRPC 失败 → 捕获转 500，不影响其他链路（Fail Fast）。

### 4.3 二级缓存（L1 Caffeine + L2 Redis）
`UrlService` 内：
```java
private final Cache<String, String> localCache = Caffeine.newBuilder()
        .maximumSize(100_000).expireAfterWrite(3, TimeUnit.SECONDS).build();   // L1 3s
private static final Duration CACHE_TTL = Duration.ofHours(24);               // L2 24h

// 缓存值格式："{urlId}|{originalUrl}"，命中即返回且能直接记 analytics，免回查 DB
private void cacheUrl(Url url) {
    String value = url.getId() + CACHE_SEPARATOR + url.getOriginalUrl();
    localCache.put(url.getShortKey(), value);
    redisTemplate.opsForValue().set(CACHE_PREFIX + url.getShortKey(), value, CACHE_TTL);
}
```
读取 `getFromCache`：先 L1（`localCache.getIfPresent`）→ 命中直接返回；未命中查 L2 Redis → 回填 L1；都没有返回 null 回源 MySQL。
`parseCached`：按 `|` 拆分；无分隔符视为旧格式（urlId=null，过渡期不记 analytics）；前缀非数字视为损坏 → 回源 DB 重新缓存。

### 4.4 跳转（公开 + 记统计）
`UrlService.redirect()`：
```java
public String redirect(String shortKey, String clientIp, String userAgent, String referer) {
    CachedUrl cached = getFromCache(shortKey);
    Long urlId; String originalUrl;
    if (cached == null) {
        Url url = urlRepository.findByShortKeyAndDeletedAtIsNull(shortKey)
                .orElseThrow(() -> new BizException(404, "URL not found"));
        urlId = url.getId(); originalUrl = url.getOriginalUrl();
        cacheUrl(url);                                  // 回填缓存
    } else { urlId = cached.urlId(); originalUrl = cached.originalUrl(); }

    if (urlId != null) analyticsAsyncService.record(urlId, clientIp, userAgent, referer); // 异步记
    return originalUrl;
}
```
> 关键：缓存值带 `urlId`，命中即能异步 `record`，**免回查 DB 即可统计**。

## 五、gRPC 通信（API 侧）

`GrpcClientConfig.java`：
```java
@Configuration
public class GrpcClientConfig {
    private final ManagedChannel channel;
    private final KeyServiceGrpc.KeyServiceBlockingStub stub;
    public GrpcClientConfig(@Value("${shortly.kgs.grpc-address:localhost:50051}") String grpcAddress) {
        String[] parts = grpcAddress.split(":");
        this.channel = ManagedChannelBuilder.forAddress(parts[0], Integer.parseInt(parts[1]))
                .usePlaintext().build();
        this.stub = KeyServiceGrpc.newBlockingStub(channel);
    }
    @PreDestroy public void shutdown() throws InterruptedException {
        channel.shutdown().awaitTermination(5, TimeUnit.SECONDS);   // 优雅关闭
    }
}
```
`KeyServiceClient.getKey()`：
```java
public String getKey() {
    try {
        KeyResponse response = grpcClientConfig.getStub()
                .withDeadlineAfter(2, TimeUnit.SECONDS)             // 2s 超时，防止 KGS 卡住阻塞创建链路
                .getKey(Empty.getDefaultInstance());
        return response.getKey();
    } catch (StatusRuntimeException e) {
        throw new RuntimeException("Failed to generate short key", e);
    }
}
```
**学习要点**
- 阻塞 Stub（同步），但 KGS 取号是 `RPOP` 毫秒级，2s 超时足够。
- 连接用 `@PreDestroy` 优雅关闭（`shutdown()` + 等 5s），避免池泄漏。
- 默认地址 `localhost:50051`，生产改 `shortly.kgs.grpc-address`。

## 六、鉴权与用户上下文

### 6.1 网关注入（WebFlux）
Gateway `JwtAuthGlobalFilter` 验签 JWT 后，向请求头注入 `X-User-Id` / `X-User-Role` / `X-Device-Id`，再 `lb://vtsl-shortlink-api` 转发。Gateway 本身**不绑 ScopedValue**（无 Servlet API）。

### 6.2 下游绑定 ScopedValue
`UserContextFilter.java`（Servlet Filter，api 模块 `scanBasePackages` 已扫描 vtslcommon.filter）：
```java
String userIdStr = httpRequest.getHeader("X-User-Id");
Long userId = userIdStr != null ? Long.parseLong(userIdStr) : null;
bindAndRun(userId, role, deviceId, () -> chain.doFilter(request, response));   // ScopedValue.where(...).run(...)
```
→ 整请求链路内 `UserContext.currentUserId()` 可用。**本地直连 8085 加 `X-User-Id: 1` 头即可当登录**，便于测试。

### 6.3 方法级鉴权
`AuthInterceptor.java`（只对 Servlet 生效 `@ConditionalOnWebApplication`）：
- 有 `@PublicApi` → 直接放行（redirect 用）。
- 有 `@RequireAuth`/`@RequireRole` 且 `X-User-Id` 为 null → 401。
- 设备在线检查：`active_token:{userId}:{deviceId}` 不存在（被踢）→ 401。
- `@RequireRole` 校验 `RoleEnum`。

### 6.4 网关路由
`application.yml`：
```yaml
routes:
  - id: shortlink-api-service
    uri: lb://vtsl-shortlink-api
    predicates:
      - Path=/api/v1/**
gateway.auth.public-get-paths: '/api/v1/url/redirect/**'   # 仅 GET 免 JWT
```

## 七、限流（Redis 固定窗口 Lua）

`RateLimit` 注解（`@RateLimit(limit=5, windowSeconds=60)`）→ `RateLimitInterceptor.preHandle`：
```java
String key = "rate_limit:" + ip + ":" + request.getRequestURI();
if (!limiter.tryAcquire(key, rl.limit(), rl.windowSeconds())) {
    response.setStatus(429); response.getWriter().write("{\"error\":\"Too Many Requests\"}");
    return false;
}
```
`RedisFixedWindowLimiter.tryAcquire()`（Lua 原子）：
```lua
local current = tonumber(redis.call('get', key) or '0')
if current >= limit then return 0 end
redis.call('incr', key)
if current == 0 then redis.call('expire', key, window) end   -- 首字才设过期
return 1
```
**学习要点**
- 固定窗口（非滑动）：实现简单、Lua 原子无竞态；缺点是窗口边界临界秒可放 2×limit 流量（够用即可）。
- 维度：`IP + URI`，粒度到接口（如 shorten 5/60s、redirect 50/60s）。
- 与简历「网关限流」互补：这里业务层再做一道，防绕过网关直连。

## 八、点击统计 Analytics

### 8.1 异步记录
`AnalyticsAsyncService.record()`（`@Async("shortlyAsyncExecutor")`）：
```java
urlRepository.incrementClicks(urlId);                 // MySQL 点击数 +1
String country = geoIpService.countryOf(ip);          // GeoIP
var uaInfo = userAgentParser.parse(userAgent);        // UA 解析
Analytics a = new Analytics();
a.setUrlId(urlId); a.setIpAddress(ip); a.setCountry(country);
a.setDevice(uaInfo.device()); a.setBrowser(uaInfo.browser()); a.setOs(uaInfo.os());
analyticsRepository.save(a);                          // 落 t_analytics
```
- 全包 try-catch：统计失败不影响跳转主链路（**统计是旁路**）。
- 异步线程池 `shortlyAsyncExecutor`（见 `AsyncConfig`，不阻塞 redirect 响应）。

### 8.2 GeoIP（`GeoIpService`）
- 优先读 Redis 缓存 `ip-country:{ip}`（24h TTL）。
- 本地地址（`127.0.0.1`/`::1`）直接返回 `Localhost`。
- 远程用 `ipapi.co/{ip}/json/` 查 `country_name`，容错返回 `Unknown`。
- 超时 2s（`shortly.geoip.timeout-seconds`），失败不影响主流程。

### 8.3 UA 解析（`UserAgentParser`）
- 纯字符串匹配：`bot/mobile` → device；`Edg/Chrome/Firefox/Safari` → browser（带版本）；`Windows/iOS/Android/Mac/Linux` → os。
- 无第三方库，轻量自实现。

### 8.4 查询统计
`AnalyticsService.getAnalytics()`：校验 `urlId` 归属当前用户（`userId.equals(url.getUserId())`）→ `findByUrlIdOrderByClickedAtDesc` → 转 `AnalyticsItem`。越权访问返回 404（不暴露他人数据）。

## 九、网关短码格式校验

`ShortCodeValidationFilter`（Gateway GlobalFilter，`HIGHEST_PRECEDENCE+10`，**早于鉴权**）：
```java
// 只校验 GET /s/{shortCode}
if (!method.equals("GET") || !path.matches("^/s/[^/]+$")) return chain.filter(exchange);
String shortCode = path.substring("/s/".length());
if (!isValid(shortCode)) { exchange.getResponse().setStatusCode(400); return ...; }
```
- 算法码：`^[PAL][1-9A-HJ-NP-Za-km-z]{1,11}$`（Base58，去 0 O I l 防混淆）。
- DB 码：`^[a-zA-Z0-9]{2,20}$`。
- **纯内存正则**，微秒级，非法短码直接 400，不进后端 → 减少无效负载。

> 注意：此 Filter 校验的是旧版 `/s/{code}` 短链（simple 模块）路径；新版 api 的 `/api/v1/url/redirect/{shortKey}` 由 `@PublicApi` 放行，短码合法性在 `redirect()` 内靠 DB 查不到返回 404 保证。

## 十、关键时序图

### 10.1 创建短链（成功路径）
```
POST /api/v1/url/shorten
  Gateway: JWT 验签 → 注入 X-User-Id → 路由
  UrlController.create
    AuthInterceptor: @RequireAuth + X-User-Id 非空
    RateLimitInterceptor: rate_limit:{ip}:/api/v1/url/shorten Lua 计数
    UrlService.create
      ├─ existsByOriginalUrlAndUserIdAndDeletedAtIsNull (MySQL) 防重复
      ├─ KeyServiceClient.getKey() ──gRPC 2s──▶ KGS.getKey
      │     ├─ LLEN < 200 → generateBatch(1000): Mongo insert + Redis LPUSH
      │     ├─ RPOP → Mongo CAS available→used → 返回 key
      ├─ existsByShortKey (MySQL)
      ├─ save(Url) (MySQL, short_key unique)
      └─ cacheUrlAsync: Caffeine + Redis(url:{key}, 24h)
  返回 CreateUrlResponse(shortKey)
```

## 十一、面试自问自答（必背）

| 问题 | 回答 |
|---|---|
| 短码会重复吗？ | Base62 6 位 ≈ 568 亿空间；Mongo `shortkeys.key` 唯一索引兜底；发放 CAS 保证同码只发一次；MySQL `t_url.short_key` 再兜底。 |
| 创建链路为什么快？ | 取号是 `RPOP` O(1)，短码早已预生成入队，无现场算码、无锁竞争；KGS 2s 超时 Fail Fast。 |
| 为什么用 Redis List 当队列？ | `LPUSH`+`RPOP` = FIFO，Redis 单线程原子，多实例安全，O(1) 无竞争，比数据库自增快。 |
| Redis 队列空/写失败怎么办？ | 阈值触发同步补货；生成批次 `DuplicateKeyException` 整批重试；发放端 `MAX_ISSUE_ATTEMPTS=3` 兜底。⚠️先 Mongo 后 Redis 的顺序隐患见 3.3。 |
| 二级缓存怎么防雪崩？ | L1 Caffeine 3s 拦截热点消除网络 IO；L2 Redis 24h；可补「TTL 随机抖动」更稳。 |
| 缓存命中怎么记统计还不回查 DB？ | 缓存值带 `urlId`，命中即异步 `record(urlId,...)`。 |
| gRPC 调用挂了？ | `KeyServiceClient` 2s 超时 → `create()` 捕获抛 500「生成短码失败」，不影响其他链路。 |
| 限流算法？ | 固定窗口（Redis Lua 原子 incr+expire），维度 IP+URI；边界临界可放 2×limit，业务够用。 |
| 统计会影响跳转性能吗？ | 不会，`@Async` 异步 + 全包 try-catch，是旁路，失败不影响主流程。 |
| 短码防枚举吗？ | 是，`SecureRandom` 随机 6 位 Base62，不可预测。 |
