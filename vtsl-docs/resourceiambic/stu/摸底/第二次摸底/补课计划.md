## 第 1 天：Spring IoC + Bean 生命周期

**背诵（必须背到默写）**
- Bean 生命周期 6 步：实例化 → 属性填充 → Aware 接口回调 → BeanPostProcessor 前置 → InitializingBean/init-method → BeanPostProcessor 后置（+ destroy 销毁）
- 每步一句话职责：实例化（反射建对象）、属性填充（@Autowired/@Value）、Aware（感知容器）、BPP 前置（@Autowired 就是在这里做的）、初始化（业务自定义 init）、BPP 后置（**AOP 代理挂载点**）
- BeanFactory（懒加载、基础容器）vs ApplicationContext（立即加载 + 事件/AOP/国际化/环境）

**理解**
- 容器原理 = 反射 + 注册表 + 扩展点（Aware/BPP）
- 项目锚点：你在秒杀项目里写的 @Service 类，被容器创建的全过程，走的就是这 6 步

**自测**：默写 6 步；口述"你的 @Service 从创建到能用，中间发生了什么"

## 第 2 天：Spring AOP + 三级缓存

**背诵**
- 三级缓存三层：一级（成品 Map）→ 二级（半成品，提前暴露的早期引用）→ 三级（ObjectFactory 工厂，延迟生成代理）
- 为什么必须是三级：需要"提前暴露引用"和"提前生成 AOP 代理"两个需求冲突——二级存引用、三级存工厂延迟决策
- 构造器注入为什么不行：构造器必须拿到完整依赖，无法提前暴露半成品
- 代理选择：有接口 → JDK 动态代理（Proxy + InvocationHandler，调用转发 invoke）；无接口 → CGLIB（生成子类字节码）；Spring Boot 2 默认 CGLIB

**理解**
- 纠正摸底臆想：JDK 代理不是"基于 vtable 生成代码"，是 Proxy 运行时生成实现类 + 调用转发
- 关联打通：BPP 后置 = AOP 代理挂载位置（第 1 天知识今天用上）

**自测**：默写三级缓存三层 + 为什么三级；口述"A 依赖 B、B 依赖 A，Spring 怎么处理"

## 第 3 天：Spring 事务

**背诵**
- 7 种传播行为：REQUIRED（默认，加入已有事务）/ REQUIRES_NEW（挂起旧事务开新事务）/ SUPPORTS / NOT_SUPPORTED / MANDATORY / NEVER / NESTED（Savepoint 嵌套）
- REQUIRED vs REQUIRES_NEW：前者异常一起回滚，后者互不影响
- @Transactional 失效 5 场景：private / 同类 this 调用 / 异常被 catch 吞掉 / 抛 checked 异常 / 类不在容器管理
- **失效原因一句话 = AOP 代理拦截范围**（今天把摸底里"会代理不会失效"的断裂补上）

**理解**
- 项目锚点：秒杀扣库存方法上的 @Transactional，为什么自调用会失效——想想你是不是有同类调用的代码

**自测**：口述"为什么 private 方法上的 @Transactional 不生效"（用代理讲）；默写 7 种传播行为

## 第 4 天：网络三件套（TCP）

**背诵**
- 三次握手：SYN → SYN+ACK → ACK；为什么不是两次（防历史连接、防服务器资源浪费）
- 四次挥手：FIN → ACK → FIN → ACK；为什么是四次（半关闭，两个方向各自关闭）
- TCP vs UDP：可靠/连接/有序/流式 vs 不可靠/无连接/报文——场景：文件传输/HTTP vs 音视频/游戏/直播

**理解**
- 画图复述：把握手挥手画一遍再讲一遍（这个题几乎每场必问）

**自测**：口述三次握手完整过程 + "为什么不是两次"

## 第 5 天：OS 两题 + 死锁

**背诵**
- 死锁四条件：互斥 / 持有并等待 / 不可剥夺 / 循环等待；预防 = 破除任一条件（如一次性申请所有资源）
- 进程 vs 线程：资源拥有者 vs 调度单位；切换代价（进程上下文切换重、线程轻）；通信（进程 IPC vs 线程共享内存）

**理解**
- 关联打通：死锁 → 连接模块一锁机制；线程 → 连接 M5 线程创建——并入"并发与集合"合并大题

**自测**：口述"Java 里怎么避免死锁"

## 第 6 天：消息队列基础（Kafka）

**背诵**
- MQ 三大作用：解耦 / 异步 / 削峰（对应秒杀：异步落库、削峰填谷）
- Topic / Partition / Consumer Group 三概念：Topic 逻辑队列，Partition 物理分片（并行度），Consumer Group 内互斥消费、组间订阅
- 顺序性保证：同一 Partition 内有序，按业务 key 路由到同一 Partition
- 偏移量提交：自动（可能重复/丢失）vs 手动（精确一次需要幂等配合）

**理解**
- 项目锚点：秒杀链路里 Kafka 异步落库——你项目里已经在用，把"为什么这么设计"说出来就是答案
- 同步 vs 异步：同步实时强一致（OpenFeign/Dubbo），异步解耦削峰（MQ）

**自测**：口述"你项目里为什么用 Kafka 做异步落库"

## 第 7 天：排查模板 + 记忆卡总攻

**背诵（一套模板通吃排查题）**
- 通用四段：定位慢在哪层 → 数据库（慢 SQL/锁等待）→ 外部依赖（超时/重试/熔断）→ JVM（GC 频繁/线程阻塞）
- CPU 100% 六步：top 找进程 → top -Hp 找线程 → tid 转十六进制 → jstack grep → 定位代码行 → 看 GC/导堆分析
- 接口变慢/接口挂了 = 同一模板换主语；内存泄漏 = jmap dump + MAT 分析大对象

**记忆卡总攻清单**（全部 P0 背诵项，连背一遍）
- 线程池铁三角：7 参数 + 4 步流程 + 4 拒绝策略 + 4 队列
- CMS 四阶段：初始标记 → 并发标记 → 重新标记 → 并发清除（+ 碎片化缺点）
- 双亲委派链：loadClass 流程 + 打破场景（JDBC/SPI/线程上下文类加载器）
- SOLID 五原则一句话
- CHM 一句话：桶空 CAS + 桶非空 synchronized + ForwardingNode 协助扩容
- volatile→DCL 一句话：禁止指令重排，防半初始化对象
- RDB 触发：save 3600 1 / 300 100 / 60 10000
