### 三、逐题弱点分析

#### 题1：线程池核心参数 + 处理流程（4/10）

**表现**：说了"7 个参数"但内容是 9 个混杂物（把"空闲线程""临时线程"这种运行时概念当参数）；处理流程**完全没答**。

**具体缺陷**：
1. 术语不精确：说"淘汰策略"（应为 handler/拒绝策略）、"阻塞队列"（应为 workQueue），面试官会判定"没系统学过"
2. 概念混淆：核心线程/临时线程是运行时角色，不是构造参数——说明参数是"印象记忆"而非"理解记忆"
3. 处理流程 4 步空白：这是本题核心，也是线程池唯一必考流程，说明从未演练过任务从提交到执行的完整路径

**知识缺口**：7 参数中英对照、4 步处理流程（核心满→进队列→队列满→开非核心→全满→拒绝）、execute() 的源码路径

#### 题2：四种拒绝策略（0/10）

**表现**：完全说不出来。

**具体缺陷**：
1. 纯记忆项、零理解门槛，0 分 = 从未刻意背过
2. 连"实际项目选哪个"也没答——没有工程经验联想，哪怕答"选 CallerRunsPolicy 因为不丢任务"也能拿 2 分
3. 这是线程池"铁三角"之一，面试几乎每场都问，失分代价最高

**知识缺口**：4 种策略的名字、行为、默认值；CallerRunsPolicy 的"反压"思想

#### 题3：四种工作队列（2/10）

**表现**：说出"有界队列"和"线程等待其他线程直接分发执行"两个模糊印象，叫不出 SynchronousQueue / ArrayBlockingQueue 的名字。

**具体缺陷**：
1. 记忆没有建立"概念 → 类名 → 特性"的完整索引，只有残影
2. 特性维度不完整：有界/无界、数组/链表、是否存储元素、公平性选项全缺
3. 不知道工程后果：LinkedBlockingQueue 不设容量会 OOM
4. 没有与默认线程池建立关联（CachedThreadPool 用 SynchronousQueue、FixedThreadPool 用 LinkedBlockingQueue）——这正是面试官爱追问的连接点

**知识缺口**：4 队列逐个背特性 + 与 Executors 默认线程池的对应关系

#### 题4：volatile（4/10）

**表现**：结论"保证可见性和有序性，不能保证原子性"完全正确，但被追问"为什么不能保证原子性"时当场放弃。

**具体缺陷**：
1. **结论导向型记忆**：知道"是什么"，不知道"为什么"——这是全模块最普遍的硬伤
2. 原子性解释缺失：说不清 `i++` 是"读→改→写"复合操作、两个线程同时读到旧值的问题
3. 底层机制全缺：内存屏障、JMM 主内存/工作内存模型、DCL 单例半初始化对象重排例子
4. 答题策略问题：答不上来直接说"不说了"跳过，而不是尝试组织

**知识缺口**：JMM 模型、内存屏障、happens-before、DCL 与 volatile 的关联

#### 题5：wait 放 while + notify/notifyAll + 虚假唤醒（4/10）

**表现**：说"if 的话 wait 一次没成功后面就不执行了，while 可以重复执行"——方向沾边但**根本不是核心原因**；虚假唤醒明确说"不懂"。

**具体缺陷**：
1. while 的真正作用没说到：唤醒后条件可能仍不满足（被别的线程抢先），必须回到循环顶重新检查——被理解成了"重试机制"
2. 虚假唤醒（OS 层面、JLS 明确允许）完全空白
3. 没提到 wait 必须在 synchronized 内、notify 是随机唤醒具有不确定性

**知识缺口**：虚假唤醒的定义与来源、notifyAll 下"资源不够抢"的场景、线程状态转换

#### 题6：AQS + ReentrantLock + 公平/非公平（6/10）🟢 本轮最好

**表现**：state 含义（0 空闲 / 1 占用 / >1 重入）说对；公平锁"先看队列有没有等待者"、非公平锁"直接抢"说对。

**具体缺陷**：
1. 把 AQS 核心概括为"CAS"不完整——准确说法是 **CAS + state + CLH 双向队列**，CLH 队列这个关键词完全没提
2. 不知道线程获取锁失败后"封装成 Node 入队 + LockSupport.park 挂起"的完整机制
3. 公平锁的表述缺"前驱节点"精确概念
4. 没提 AQS 的独占/共享两种模式——这正好与题 7 的 CountDownLatch 是同一体系的，没打通

**知识缺口**：CLH 队列结构、Node 状态、acquire/release 模板方法、LockSupport.park/unpark

#### 题7：CountDownLatch vs CyclicBarrier（4/10）

**表现**：门栓比喻、一次性 vs 可循环用 说对；但"state 到底叫什么"说不上来，还口误说成"StackOverflow"；场景例子一个举不出。

**具体缺陷**：
1. 底层机制空白：不知道 CDL = AQS 共享模式（state 即计数器，countDown CAS 减 1，归零放行 await）；CB = ReentrantLock + Condition
2. **知识孤立**：CDL 和题 6 的 AQS 是同一条知识线的两个实例（独占 vs 共享），却完全没关联上——说明知识是散点，没有建立体系
3. 举不出真实场景（主线程等子任务汇总 / 多线程分阶段同步），工程联想弱

**知识缺口**：AQS 共享模式、await/countDown 流程、典型场景各一个

### 六、针对性复习方案

**第 1 步 · 背诵清单（记忆层，当天完成）**
- 7 参数：corePoolSize / maximumPoolSize / keepAliveTime / unit / workQueue / threadFactory / handler
- 4 步流程：核心满 → 进队列 → 队列满开非核心 → 全满执行拒绝
- 4 拒绝策略：Abort（抛异常）/ CallerRuns（提交者自己干，反压）/ Discard（静默丢）/ DiscardOldest（丢最老）
- 4 队列：Array（有界数组）/ Linked（默认无界，易 OOM）/ Synchronous（不存元素直接交接，CachedThreadPool 用）/ Priority（无界排序）
- 每项配一个口诀或一行表，**背到能默写**。

**第 2 步 · 机制补课（理解层）**
- volatile → 内存屏障 + JMM 主存/工作内存 + i++ 复合操作 + DCL 重排例子

- AQS → CLH 队列 + Node + park/unpark + 独占/共享双模式
- 打通：ReentrantLock（独占）→ Semaphore（共享）→ CountDownLatch（共享计数）→ CyclicBarrier（Lock+Condition），画一张关联图

**第 3 步 · 口述训练（输出层）**
- 每个知识点写一段 80~120 字的标准回答稿（含标准术语）
- 照着稿子口述 3 遍，再脱稿口述，录音回听
- 每题回答按"结论 → 机制 → 例子"三段组织

**第 4 步 · 场景绑定（工程层）**

- CDL：主线程等 10 个查询任务完成再汇总
- CB：多线程分阶段计算（每阶段同步后进入下阶段）
- 队列：订单系统用有界队列防止 OOM

### 三、逐题弱点分析

#### 题1：运行时数据区（6.5/10）—— 全模块最好的一题

**表现**：框架完整——私有/共享划分 ✅、HotSpot 栈合并 ✅、对象结构三件套 ✅、vtable 多态分派 ✅、栈帧四件套 ✅。

**具体缺陷**：
1. **程序计数器位置搞错**：说"程序计数器在虚拟机栈里"，实际是独立区域
2. **元空间内容没说完**：只说出类信息/接口信息，漏了运行时常量池、方法字节码、字段方法信息
3. 术语谐音错误：vtable 说成"waitable"、标记位图说成"Classing"（下文诊断有分析）
4. 跑偏：答运行时数据区时扯到反射 setAccessible——知识点本身没错但答非所问

#### 题2：对象创建流程（6/10）

**表现**：链路说得很顺——类加载检查 → TLAB 分配 → top 指针 → 满后 CAS 抢新 TLAB → free list → 零值初始化/对象头/构造方法（未展开）。

**具体缺陷**：
1. TLAB 位置表述绕：说"当前 Region 的空闲区"，标准说法是"Eden 区里的一块线程私有空间"
2. 零值初始化、对象头、构造方法三个环节**明确说"忘记了"**——流程主干对，但尾段没巩固
3. 加分项：JDK 25 压缩对象头、ZGC 染色指针这些前沿点了解（说明有持续看新资料）

#### 题3：分代假说（5/10）

**表现**：朝生夕灭的直觉有，15 岁晋升、复制/标记整理的选择都对。

**具体缺陷**：
1. **"分代假说"是什么没说出来**：正式表述"绝大多数对象朝生夕灭"——这是本题核心，反而最没答
2. **没解释"为什么"新生代用复制、老年代用标记整理**：答案在存活率（新生代存活 <10%，复制代价小；老年代存活率高，复制代价大）
3. 这是典型的"结论对、论证缺"，和模块一 volatile 同一模式

#### 题4：G1 收集器（3/10 → 补充后 6.5/10）

**表现**：第一轮只答"可预测停顿时间+Region"，补充后量大增——2048 Region、四角色、CSet、RSet、Card Table、SATB 全提到了。**这是全模块（甚至整个摸底）最有信息量的一题**。

**具体缺陷**：
1. **Mixed GC 触发条件搞错**：以为"堆使用率 45% 触发 Mixed GC"，实际是 IHOP 默认 45% 触发的是**并发标记周期**，Mixed GC 在标记完成后按 Region 回收价值排序触发
2. 并发标记阶段"不是很懂"——不知道它是和业务线程同时跑的、从 GC Roots 遍历全堆的标记过程
3. SATB 方向对但没想通：知道"标记开始时拍快照"，但没理解"写屏障记录被删除的旧引用防止漏标"这一机制细节
4. **知识是"听说"状态**："今天下午刚纠正学了，现在又一下子想不起来"——短期记忆未固化（下文诊断有分析）

#### 题5：CMS（2/10）

**表现**：只说出"碎片化严重 → 触发 Full GC → STW 长"，**四阶段完全没答**，并自称"没怎么学它"。

**具体缺陷**：
1. 四个阶段（初始标记→并发标记→重新标记→并发清除）是纯记忆项，完全空白——和模块一拒绝策略 0 分同款
2. 碎片化的因果链只答出半截：没说出来"标记清除不压缩 → 碎片 → 退化 Serial Old 触发 Full GC"的完整链条
3. 浮动垃圾、CPU 敏感两个缺点没提

#### 题6：双亲委派（4/10）

**表现**：loadClass 源码流程说得不错（查缓存→parent→Bootstrap→回退），安全性目的也对。自述"这是我学习以来最不理解的地方"。

**具体缺陷**：
1. **"为什么要打破"逻辑链断裂**：提到 JDBC DriverManager 但说不清因果（Bootstrap 加载的 DriverManager 找不到 classpath 下的驱动 → 需要线程上下文类加载器反向委托）
2. **SPI 完全没理解**：原话"SPI 我现在还是没有理解什么东西"——本质就是"接口父加载器加载、实现子加载器加载"，和 JDBC 例子是同一个逻辑，说明知识的"点"没有连成"链"
3. 怎么打破答出"重写 loadClass"，没说出更推荐的 findClass 重写和 setContextClassLoader

#### 题7：诊断工具 + CPU 100% 排查（2.5/10）

**表现**：jps -l、jstat -gc 说对，jstack"一看就是虚拟机栈"（知道大概），jmap 完全不知道。排查思路只说出"看堆状态"，六步流程没建立。工具名全说成谐音（gstate/Gmap/GPS）。

**具体缺陷**：
1. 四个工具背不全——纯记忆项，同款失分

### 三、逐题弱点分析

#### 题1：IOC + BeanFactory vs ApplicationContext（3/10）

**表现**：核心思想对（对象创建管理交给容器）✅、基于反射 ✅、但**自述"脑子里没有场景""没有概念"**，且 BeanFactory vs ApplicationContext 完全没答。

#### 题2：Bean 生命周期（2/10）

#### 题3：三级缓存循环依赖（3/10）

**表现**：A 依赖 B、B 依赖 A 场景 ✅、"实例化完进缓存→查缓存→发现循环"骨架 ✅。但**三个缓存分别是什么、为什么必须三级、构造器注入为什么解决不了**全没答。自述"看过并且学了，但现在忘干净了"。

**具体缺陷**：
1. **遗忘型失分**（区别于从未学）：场景骨架还在，说明学过且内化过一部分，缺的是细节层——这类复习成本最低
2. 三个缓存的角色没建立：一级（成品 Map）、二级（半成品，提前暴露的早期引用）、三级（ObjectFactory 工厂，延迟生成代理）——"为什么三级"的答案恰恰藏在三级缓存里（需要提前生成 AOP 代理又不想破坏早期引用）
3. 构造器注入为什么不行：构造器里必须拿到完整依赖，无法提前暴露半成品——没答

#### 题4：AOP（4.5/10）—— 本模块最好

**表现**：动态代理 ✅、JDK 基于接口 ✅、CGLIB 生成字节码（补充后）✅、Spring Boot 2 默认 CGLIB ✅。

**具体缺陷**：
1. **臆想式知识**："JDK 动态代理基于 vtable 生成代码"——本人承认是"自己臆想的"。实际是 Proxy + InvocationHandler 运行时生成实现类，方法调用转发到 invoke()。vtable 是 JVM 层面的名词，被错误迁移到这里
2. "什么时候选哪种"没答：接口存在→JDK，无接口或目标类非接口→CGLIB（Boot 2 默认 CGLIB 与目标无关，是框架配置）
3. 缺"代理对象→方法拦截→事务/日志"的完整链路概念

#### 题5：事务传播行为（0/10）

**表现**：自述"不知道，不会，一点不了解"。7 种传播行为一个说不出。

**具体缺陷**：

3. REQUIRED vs REQUIRES_NEW 的区别（是否共用事务/异常一起回滚 vs 互不影响）没建立

#### 题6：@Transactional 失效场景（1/10）

**表现**：知道 private 不行 ✅，**原因不懂**。

**具体缺陷**：
1. **同源知识未连接（关键发现）**：题 4 他答得出"Spring 事务基于动态代理"，题 6 需要解释"private 方法无法被代理拦截，所以事务注解不生效"——两个题是同一个知识点，却连不起来。直接证据："点不成链"模式在模块三的极端表现

### 三、逐题弱点分析

#### 题1：MySQL 索引（6/10）

**表现**：B+ 树矮胖、数据只在叶子、非叶子只存索引、叶子双向链表支持范围查询、B 树非叶子也存数据导致树更高、聚簇/非聚簇区别——全对，输出非常顺。

**具体缺陷**：
1. **B 树不支持范围查询的原因没说清**：因为数据分散在所有节点，范围查询需中序遍历整棵树；B+ 树叶子链表直接顺序扫
2. 红黑树论证缺一层：只说出"树高"，没说"红黑树是二叉树每个节点只存一个值，数据量大时树高超 B+ 树 → 磁盘 IO 次数多"（IO 次数这个核心词没出现）
3. 自述"红黑树学 HashMap 时学过，现在早忘了"——遗忘模式在边缘知识点重现

#### 题2：事务隔离级别（7.5/10）—— 摸底以来最高分题

**表现**：四个级别、脏读、RC 每次查询生成 read view、RR 只生成一次、Next-Key Lock 解决幻读、串行化性能差——链路完整、表述流畅。

**具体缺陷**（都是"说了 A 没说 B"型）：
1. RC 解决了脏读**没明确说出来**（只说了 RC 会产生不可重复读）
2. RR 解决了不可重复读**没明确说出来**
3. 快照读/当前读的双通道表述完整（MVCC 处理快照读、Next-Key Lock 处理当前读）——这部分是亮点

#### 题3：MVCC（6/10）

**表现**：read view + trx_id 隐藏字段 + undo log 三要素 ✅、可见性判断逻辑（新事务 ID 不在 read view → 走 undo log 读历史）✅。

**具体缺陷**：
1. **版本链回溯机制是盲点（本人主动发现）**："undo log 怎么读到历史版本的，具体怎么实现？现在又发现了一个盲点，这是之前学习没接触过的"——缺 roll_pointer 指针串联多个历史版本这一环
2. **正面信号**：这是他摸底以来第一次**主动发现并报告自己的盲点**——自我评估能力在提升

#### 题4：Redis 数据结构（5/10）

**表现**：五大数据结构 ✅、Redis 7 底层结构（Listpack/Dict/SDS/SkipList/QuickList）✅、SDS 全称+作用 ✅、QuickList=链表+节点是 Listpack ✅、Dict 支撑 Hash/Set ✅、SkipList 支撑 ZSet ✅——**底层结构这块答得出乎意料地扎实**。

**具体缺陷**：

### 三、逐题弱点分析

#### 题1：HashMap（7.5/10）—— 摸底以来最强单题

**表现**：JDK7/8 演进、头插法环形链表死循环、树化条件（≥8 且容量 ≥64）、高位扰动、`hash & (capacity-1)` 等价取模、桶空直放、key 同替换、key 不同尾插——链路完整顺滑。

**具体缺陷**：

#### 题2：ConcurrentHashMap（4/10）—— 表述混乱（本人澄清为口误）

**表现**：1.7 分段锁/16 段 ✅、1.8 桶级锁 ✅、锁粒度变细 ✅。但笔录里出现"桶级锁其实并不能保证线程安全"一句，原评估 AI 据此扣分。**本人澄清是口误**——他想表达的是 1.7 分段锁、1.8 桶级锁的演进，并没有认为桶级锁不安全。

> 📌 **口误原因标注（本人确认）**：当时已深夜 11 点，学了一天、面了一天，处于疲劳状态，口语表达出现自我怀疑式的串词。CHM（ConcurrentHashMap）是线程安全的 Map 这一点用户非常清楚，无需补课，该题失分属疲劳口误而非知识性错误。评估报告对此保留更正记录，避免误伤后续复习规划。

**要点确认**：无论如何表述，1.8 的完整机制值得口头确认一遍：**桶空 CAS 无锁插入、桶非空 synchronized 锁头节点、ForwardingNode 支持多线程协助扩容**——三层协同保证线程安全。这句话能完整说出来，这道题就是满分。

**未展开**：1.7 的 Segment 继承 ReentrantLock、每段独持锁、读操作完全无锁（volatile 保证可见性）的完整机制。

#### 题3：ArrayList vs LinkedList（6/10）

**表现**：动态数组 vs 链表、随机读 O(1) vs O(n)、修改只需改指针、尾部插入/删除 O(n) 迁移 —— 复杂度都对。

**缺陷**：
1. **"LinkedList 适合改多"不准确**：LinkedList 的优势只在**头/尾插入删除 O(1)**；中间位置插入仍要先 O(n) 定位。实际开发中 ArrayList 因 CPU 缓存局部性在大部分场景反而更快——这个反直觉结论没建立
2. 场景判断停留在"复杂度书"层面，没有工程观

#### 题4：创建线程方式（6/10）

**表现**：new Thread/Runnable/Callable/线程池/虚拟线程 5 种列全。

**缺陷**：区别没展开——Callable 可返回+抛异常需配 FutureTask、线程池复用避免创建销毁开销。列了名但没讲"为什么选它"。

#### 题5：synchronized vs ReentrantLock（6.5/10）

**表现**：JVM 层 vs JDK 层、对象头 lock record/object monitor、wait set、CAS、自动/手动释放——机制层全对。

**缺陷**：
1. ReentrantLock 三个杀手锏没提：可中断等待、tryLock 超时、Condition 条件变量（公平锁也没提）
2. synchronized 的锁升级（偏向→轻量→重量）没提——这是本题最大的加分面

**表现**：7 参数全背出，且主动说"模块一已答过就不展开了"——**跨模块知识复用意识出现**（正面信号）。

### 三、弱点分析

1. **全部 6 题是纯记忆+固定流程型**（握手过程、状态码、四条件）——正好是你最弱的记忆层，但这次是白纸一张，反而没有"半桶水"的干扰
2. **题4（URL 全过程）是综合性大题**，能串起 DNS/TCP/HTTP/渲染，是面试官最爱考"讲一个完整故事"的题——对你不利，因为需要结构化叙述能力
3. **OS 部分（进程线程/死锁）与并发模块强相关**：死锁四条件（互斥/持有并等待/不可剥夺/循环等待）学完可以反哺模块一的并发理解；进程线程区别则和 M5 的线程创建呼应

### 四、诊断与优先级

- **空白原因**：不是遗忘、不是学不会，是**没学过+框架里排在后面**（READ.md 学习顺序里模块八排倒数第三）
- 面试频率：TCP 握手是**超高频**，几乎每场都问——不能按学习顺序把它拖到最后
- 建议优先级：🔴 P0（背三件套：握手挥手、TCP vs UDP、HTTP vs HTTPS）；🟠 P1（进程线程、死锁四条件）；🟡 P2（URL 全过程——留到口述训练阶段）

### 五、复习方案

**背诵清单**：
- 三次握手：SYN → SYN+ACK → ACK；为什么不是两次（防历史连接/防服务器资源浪费）
- 四次挥手：FIN → ACK → FIN → ACK；为什么是四次（半关闭，数据单向传输完后各自关闭）
- TCP vs UDP：可靠/连接/有序/流式 vs 不可靠/无连接/报文——场景（文件传输 vs 音视频/游戏）
- HTTP vs HTTPS：443/证书/对称+非对称加密——HTTPS 握手流程画一遍
- 死锁四条件 + 预防思路（破除任一条件）
- 进程 vs 线程：资源拥有者 vs 调度单位、切换代价、通信方式

**与其他模块联动**：死锁四条件 → 连接模块一锁机制；进程线程 → 连接 M5 线程创建——学完写进"并发与集合"合并大题。

### 三、逐题弱点分析

#### 题1：设计模式（6/10）—— 项目资产首次兑现

**表现**：策略模式（秒杀三种扣库存策略）、模板方法（固定流程+子类实现）、生产消费者（Kafka 异步落库）、单例（Spring bean）、工厂——**每个模式都挂在真实项目上**，这是全摸底唯一一次"场景层"拿分。

**缺陷**：
1. 工厂模式没展开（简单/方法/抽象三者的区别）
2. 常见模式漏说：观察者、装饰器、代理（这三个都该会，尤其代理和 AOP 强相关）

#### 题2：单例 DCL + volatile（4/10）—— ⚠️ 知识不迁移（重要）

**表现**：DCL ✅，但 volatile 作用说成"让其他线程实时获取锁的状态信息"。

**核心问题——知识不迁移**：模块一题 4 他把 volatile 的"可见性+有序性+不能保证原子性"说得头头是道（5 分），但**换个场景（DCL）就完全不会用**：DCL 里 volatile 的核心作用是**禁止指令重排**（`new` 三步：分配内存→初始化→引用赋值，2/3 可能重排导致拿到半初始化对象）。这是摸底最典型的一处"背了定义不会应用"——面试官问 DCL 正是为了验证你 volatile 到底懂没懂。

#### 题3：SOLID（0/10）

**表现**：未答，"设计原则我不懂，不了解这个东西"。

**缺陷**：纯记忆项+名字类，从未学过。至少要知道 S/O/L/I/D 五个名字和一句话含义（单职责、开闭、里氏替换、接口隔离、依赖倒置）——开闭原则和里氏替换还经常被追问。

#### 题4：限流器设计（6/10）—— 本轮并列最好

**表现**：Semaphore 方案（acquire/try/finally release）✅、RateLimiter ✅、AOP+自定义注解+Around 切面 ✅——**工程思维完整，有真实实现经验**。

**缺陷**：
1. 限流算法没提：固定窗口/滑动窗口/漏桶/令牌桶的区别（令牌桶=RateLimiter 的原理，本该顺口带出）
2. 分布式限流没提：Redis + Lua 原子性——正好接上 READ.md 5.5 的分布式锁/Lua 考点

#### 题5：接口变慢排查（0/10）

**表现**："不会，不说，不想说了。"未答。

**具体缺陷**：
1. **排查类题目系统性空白**：M2 CPU 100% 排查 2.5 分、本题 0 分——线上问题排查是你最大的工程盲区
