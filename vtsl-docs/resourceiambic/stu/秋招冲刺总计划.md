**AI 学习提效的正确用法：**
1. 一次会话只攻一个主题（一个知识点/一张串链图/一份口述稿）。
2. 学完立刻让我把「结论 → 机制 → 例子」写成 80~120 字标准稿，存进对应学习文档。
3. 别让 AI 一次性灌十个主题——上下文一满，前面的就丢了，等于白学。
4. 复习时把文档里的标准稿贴回对话，让我考你（问→你答→我打分纠错），闭环。

2. **Spring IoC 容器** —— 手写容器只到「实例化 → 属性填充」，初始化阶段（Aware / BPP 前后置 / init）还没学；循环依赖只学了二三级缓存 + 三级缓存 value 用 lambda 表达式生成动态代理这块。需补齐初始化阶段 + Bean 生命周期全链路。
3. **类加载机制与双亲委派** —— loadClass 前半段懂（先查缓存 → 委派父加载器），后半段（自己 findClass/defineClass）忘了；SPI 打破双亲委派、Tomcat/JDBC 为何打破、自定义类加载器隔离这些还不会。
4. **Spring AOP** —— 补：JDK 动态代理 vs CGLIB 区别、切面织入时机、事务失效经典场景（自调用、异常类型等）。
5. **Spring Boot 自动装配原理** —— `@EnableAutoConfiguration` → `spring.factories` / `AutoConfiguration.imports` → 条件注解（`@ConditionalOnClass` 等）完整链路。

## 8. P0 记忆卡清单（背诵项明细）

**并发**
- 线程池铁三角：7 参数 + 4 步流程 + 4 拒绝策略 + 4 队列
- CHM 一句话：桶空 CAS + 桶非空 synchronized + ForwardingNode 协助扩容
- volatile→DCL 一句话：禁止指令重排，防半初始化对象
- 死锁四条件：互斥 / 持有并等待 / 不可剥夺 / 循环等待
- 进程 vs 线程：资源拥有者 vs 调度单位；切换代价；通信方式

**JVM**
- CMS 四阶段：初始标记 → 并发标记 → 重新标记 → 并发清除（+ 碎片化缺点）
- 双亲委派链：loadClass 流程 + 打破场景（JDBC/SPI/线程上下文类加载器）
- G1 GC 流程：Young GC / Mixed GC / Full GC 触发条件与步骤

**Spring**
- Bean 生命周期 6 步：实例化 → 属性填充 → Aware → BPP 前置 → 初始化 → BPP 后置（+ destroy）
- 三级缓存三层：一级成品 Map / 二级半成品早期引用 / 三级 ObjectFactory 工厂
- 事务 7 传播行为：REQUIRED / REQUIRES_NEW / SUPPORTS / NOT_SUPPORTED / MANDATORY / NEVER / NESTED
- @Transactional 失效 5 场景：private / 同类 this 调用 / 异常吞掉 / checked 异常 / 非容器管理

**网络/OS**
- TCP 三件套：三次握手、四次挥手、TCP vs UDP
- HTTP vs HTTPS：明文 vs TLS 加密；端口 80 vs 443

**Redis**
- RDB 触发：save 3600 1 / 300 100 / 60 10000
- 缓存穿透/击穿/雪崩：三者区别 + 各自防护

**MQ**
- MQ 三大作用：解耦 / 异步 / 削峰
- 三概念：Topic（逻辑队列）/ Partition（物理分片）/ Consumer Group（组内互斥、组间订阅）

**排查模板**
- 通用四段：定位慢在哪层 → 数据库（慢 SQL/锁等待）→ 外部依赖（超时/重试/熔断）→ JVM（GC/线程阻塞）
- CPU 100% 六步：top 找进程 → top -Hp 找线程 → tid 转十六进制 → jstack grep → 定位代码 → 看 GC/导堆
- 内存泄漏：jmap dump + MAT 分析大对象

**设计模式**
- SOLID 五原则一句话各一

**📌 面经新增错题卡（来自两场面试，见 `面试/复盘汇总.md`）**
- **性能指标**：P99/P95 = 排序后分位数（99% 请求延迟 ≤ 该值，衡量长尾）；吞吐量 = 单位时间事务数（QPS/TPS）
- **Kafka Broker**：集群节点，收 Producer 消息 + 持久化磁盘 + 副本 + 响应 Consumer 拉取（存储+转发核心）
- **异步防丢消息**：Producer `acks=all` / Broker 副本 / Consumer 手动提交 offset；兜底 = 定时扫描 + 死信队列 + 幂等
- **三级缓存话术**：Caffeine 挡极热点 → Redis 主查询 → DB 兜底一致性；先更 DB 再删 Redis + 延迟双删
- **inner vs left join**：inner=交集；left=保留左表全部，右表不匹配填 NULL
- **ArrayList 内存布局**：`Object[] elementData` 存堆，无参构造懒加载、首次 add 初始容量 10，满扩容 1.5 倍
- **HTTP 作用**：应用层、无状态、请求-响应模型（方法 + 状态码）
- **分页数据结构**：List/ArrayList 包装 + MyBatis-Plus `Page`/`PageHelper` 或 SQL `LIMIT`

## 9. 三张串链图大纲

**图 1：并发与集合**
AQS → ReentrantLock/synchronized 锁升级 → ThreadLocal/虚拟线程 → 线程池（参数/拒绝策略/队列）→ CHM → volatile/DCL → 死锁

**图 2：MySQL-Redis-MQ**
MySQL（B+ 树/索引/事务/MVCC/锁/Buffer Pool/Redo）↔ Redis（数据结构/持久化/过期/缓存三问题/Cache Aside/分布式锁/Lua）↔ Kafka（Topic/Partition/ConsumerGroup/顺序性/偏移）

**图 3：JVM-Spring**
类加载/双亲委派 → 运行时数据区 → 对象创建（TLAB）→ G1/ZGC → Spring IoC（三级缓存）→ Bean 生命周期 → AOP → 自动装配
