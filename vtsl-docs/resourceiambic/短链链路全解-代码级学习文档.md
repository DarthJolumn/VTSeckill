## 二、第一层：Gateway 入口（短码格式校验 + 路由）

### 2.1 短码格式校验

`vtsl-gateway/.../filter/ShortCodeValidationFilter.java` — 在认证之前（`Order = HIGHEST_PRECEDENCE + 10`）拦截非法短码，纯内存正则匹配，不进后续链路：

```java
@Component
public class ShortCodeValidationFilter implements GlobalFilter, Ordered {

    /** Base58 字符集：数字 + 大写字母(无 O I) + 小写字母(无 l) */
    private static final String BASE58 = "[1-9A-HJ-NP-Za-km-z]+";

    /** 算法码：P/A/L 前缀 + Base58(1-11位) */
    private static final Pattern ALGORITHM_CODE = Pattern.compile("^[PAL]" + BASE58 + "{1,11}$");

    /** DB 码：纯字母数字 2-20 位 */
    private static final Pattern DB_CODE = Pattern.compile("^[a-zA-Z0-9]{2,20}$");

    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        String path = exchange.getRequest().getURI().getPath();

        // 只校验 GET /s/{shortCode}
        if (!exchange.getRequest().getMethod().name().equals("GET")
                || !path.matches("^/s/[^/]+$")) {
            return chain.filter(exchange);
        }

        String shortCode = path.substring("/s/".length());

        if (!isValid(shortCode)) {
            log.warn("短码格式非法，拒绝请求: shortCode={}", shortCode);
            exchange.getResponse().setStatusCode(HttpStatus.BAD_REQUEST);
            return exchange.getResponse().setComplete();
        }
        return chain.filter(exchange);
    }

    @Override
    public int getOrder() {
        // 在认证过滤器之前执行，减少无效认证开销
        return Ordered.HIGHEST_PRECEDENCE + 10;
    }
}
```

**关键点**：
- 区分两种短码：**算法码**（`P/A/L` 前缀，来自商品/活动/直播间 ID 的 Base58 派生，≤12 字符）与 **DB 码**（纯字母数字 2-20 位，KGS 随机码落在这一档）。
- 校验放在**认证之前**：非法请求直接 400，不做无谓的 JWT 验签，节省链路开销。

## 三、第二层：api Controller 接入（鉴权 + 限流 + 接口）

### 3.1 请求进入 api 的三道关卡（顺序执行）

| 关卡 | 组件 | 职责 |
|---|---|---|
| ① | `UserContextFilter`（vtsl-common/filter） | 读 `X-User-Id/X-User-Role/X-Device-Id` 头 → `ScopedValue.where(...).run(chain)`，整个请求生命周期内 `UserContext.currentUserId()` 可用 |
| ② | `AuthInterceptor`（vtsl-common/interceptor） | `@PublicApi` 放行；`@RequireAuth` 且无 userId → 401；设备在线检查 `active_token:{userId}:{deviceId}`（被踢设备拒绝） |
| ③ | `RateLimitInterceptor`（api 本地） | `@RateLimit` 注解 + Redis Lua 固定窗口，超限 429 |

**注册方式**（`vtsl-shortlink-api/.../config/WebConfig.java`）：

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(rateLimitInterceptor)
                .addPathPatterns("/api/v1/**")
                .excludePathPatterns("/api/v1/health");

        registry.addInterceptor(authInterceptor)
                .addPathPatterns("/api/v1/**")
                .excludePathPatterns("/api/v1/url/redirect/**", "/api/v1/health");
    }
}
```

> 注意：跳转接口 `/api/v1/url/redirect/**` 是公开的（`@PublicApi`），**只过限流不过鉴权**。

**ScopedValue 绑定**（`vtsl-common/.../context/UserContext.java`）：

```java
public final class UserContext {
    public static final ScopedValue<Long> USER_ID = ScopedValue.newInstance();
    public static final ScopedValue<Integer> ROLE = ScopedValue.newInstance();
    public static final ScopedValue<String> DEVICE_ID = ScopedValue.newInstance();

    public static Long currentUserId() {
        return USER_ID.isBound() ? USER_ID.get() : null;   // 虚拟线程内同一请求链路始终有效
    }
}
```

### 3.2 Controller 接口全览

`vtsl-shortlink-api/.../controller/UrlController.java`（片段）：

```java
@RestController
@RequestMapping("/api/v1")
public class UrlController {

    @PostMapping("/url/shorten")
    @RequireAuth
    @RateLimit(limit = 5, windowSeconds = 60)          // 创建：5 次/min/IP
    public Result<CreateUrlResponse> create(@Valid @RequestBody CreateUrlRequest request) {
        Long userId = requireUserId();                 // UserContext.currentUserId()
        return Result.ok(urlService.create(userId, request));
    }

    @GetMapping("/url/{shortKey}")
    @RequireAuth
    @RateLimit(limit = 20, windowSeconds = 60)         // 详情：20 次/min/IP
    public Result<UrlDetailResponse> details(@PathVariable String shortKey) {
        Long userId = requireUserId();
        return Result.ok(urlService.details(userId, shortKey));
    }

    @GetMapping("/url/redirect/{shortKey}")
    @PublicApi
    @RateLimit(limit = 50, windowSeconds = 60)         // 跳转：50 次/min/IP（公开接口）
    public Result<String> redirect(@PathVariable String shortKey, HttpServletRequest request) {
        String clientIp = getClientIp(request);
        String userAgent = request.getHeader("User-Agent");
        String referer = request.getHeader("Referer");
        String originalUrl = urlService.redirect(shortKey, clientIp, userAgent, referer);
        return Result.ok(originalUrl);                 // 返回原始 URL，前端自行跳转
    }

    @GetMapping("/analytics/{urlId}")
    @RequireAuth
    @RateLimit(limit = 10, windowSeconds = 60)         // 统计查询：10 次/min/IP
    public Result<List<AnalyticsItem>> analytics(@PathVariable String urlId) {
        Long userId = requireUserId();
        return Result.ok(analyticsService.getAnalytics(userId, urlId));
    }

    private Long requireUserId() {
        Long userId = UserContext.currentUserId();
        if (userId == null) {
            throw new BizException(401, "Unauthorized: Id is missing from context");
        }
        return userId;
    }
}
```

**关键点**：
- 鉴权注解与限流注解**声明在方法上**，逻辑完全解耦（拦截器统一处理）。
- `requireUserId()` 从 ScopedValue 取 userId，而不是从参数/ThreadLocal（虚拟线程下 ThreadLocal 不可靠，ScopedValue 与请求生命周期绑定）。

## 四、第三层：KGS 发号服务（预生成 + 队列 + CAS）

### 4.1 核心思想：生成 / 发放 解耦

```
【生成侧】（重操作，批量）                     【发放侧】（轻操作，O(1)）
SecureRandom 随机 6 位 Base62                Redis rightPop（原子）
      │                                             │
Mongo insert(available)  ──▶ Redis List ────────────┘
      │                                             │
唯一索引防重                                    Mongo CAS(available→used)
```

### 4.2 常量定义

`vtsl-shortlink-keygenerator/.../constant/KgsConstants.java`：

```java
public final class KgsConstants {
    public static final String REDIS_QUEUE_NAME = "shortly-kgs-redis-queue";
    public static final long QUEUE_THRESHOLD = 200;    // 队列低于此值触发补货
    public static final int BATCH_SIZE = 1000;         // 每批生成量
    public static final int KEY_LENGTH = 6;            // 短码长度
    public static final int MAX_GENERATE_ATTEMPTS = 3; // 生成撞唯一索引重试上限
    public static final int MAX_ISSUE_ATTEMPTS = 3;    // 单次 getKey 出队重试上限
    public static final String STATUS_AVAILABLE = "available";
    public static final String STATUS_USED = "used";
}
```

### 4.3 随机短码生成

`vtsl-shortlink-keygenerator/.../util/Base62Util.java`：

```java
public final class Base62Util {

    private static final String CHARSET =
            "0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ";  // 62 字符
    private static final BigInteger BASE = BigInteger.valueOf(62);
    private static final SecureRandom RANDOM = new SecureRandom();

    /** 生成 [0, 62^length) 均匀随机整数，转 Base62 字符串，左补 '0' 到固定长度 */
    public static String randomKey(int length) {
        BigInteger max = BASE.pow(length);                        // 62^6 ≈ 568 亿
        BigInteger n = new BigInteger(max.bitLength(), RANDOM).mod(max);

        StringBuilder sb = new StringBuilder();
        while (n.compareTo(BigInteger.ZERO) > 0) {
            BigInteger[] div = n.divideAndRemainder(BASE);
            sb.append(CHARSET.charAt(div[1].intValue()));
            n = div[0];
        }
        while (sb.length() < length) {
            sb.append(CHARSET.charAt(0));
        }
        return sb.reverse().toString();
    }
}
```

**关键点**：
- 用 `BigInteger(bitLength, SecureRandom)` 均匀采样后取模，避免 `Random.nextInt` 的模偏差（虽然 62 不能整除 2 的幂，mod 有轻微偏差，此处容量极大可忽略）。
- **随机码 vs 顺序码**：随机不可枚举，防止他人遍历短码抓取全量短链；对比弃案 simple 的 `Redis INCR + Base62` 顺序编码可被爬取。

### 4.4 批量生成（惰性补货）

`vtsl-shortlink-keygenerator/.../service/KeyGenerator.java`：

```java
public void generateBatch(int count) {
    for (int attempt = 0; attempt < KgsConstants.MAX_GENERATE_ATTEMPTS; attempt++) {
        List<String> keys = new ArrayList<>(count);
        List<ShortKeyDocument> docs = new ArrayList<>(count);

        for (int i = 0; i < count; i++) {
            String key = Base62Util.randomKey(KgsConstants.KEY_LENGTH);
            keys.add(key);
            docs.add(new ShortKeyDocument(key, KgsConstants.STATUS_AVAILABLE, Instant.now()));
        }

        try {
            mongoTemplate.insert(docs, "shortkeys");                 // ① Mongo 落账
            redisTemplate.opsForList().leftPushAll(
                    KgsConstants.REDIS_QUEUE_NAME, keys.toArray(new String[0]));  // ② 入队
            log.info("Generated and queued {} keys", count);
            return;
        } catch (DuplicateKeyException e) {
            log.warn("Duplicate keys in batch, retrying (attempt {}/{})",
                    attempt + 1, KgsConstants.MAX_GENERATE_ATTEMPTS);
        }
    }
    throw new RuntimeException("Failed to generate keys after ... attempts");
}
```

**关键点**：Mongo 批量 insert 是**账本**（谁生成过、什么状态），Redis List 是**队列**（可用 key 池）。`DuplicateKeyException`（唯一索引兜底）重试整批——568 亿空间里碰撞概率极低，兜底几乎不会触发。

### 4.5 发放（getKey：出队 + CAS）

`vtsl-shortlink-keygenerator/.../service/KeyService.java`：

```java
public String getKey() {
    // 最多尝试 MAX_ISSUE_ATTEMPTS 次：CAS 失败（脏 key）或队列瞬时为空时取下一个
    for (int attempt = 0; attempt < KgsConstants.MAX_ISSUE_ATTEMPTS; attempt++) {
        Long queueLen = redisTemplate.opsForList().size(KgsConstants.REDIS_QUEUE_NAME);
        if (queueLen == null) {
            throw new RuntimeException("Redis unavailable");
        }

        if (queueLen < KgsConstants.QUEUE_THRESHOLD) {                 // 惰性补货
            log.info("Queue length {} below threshold {}, generating more keys",
                    queueLen, KgsConstants.QUEUE_THRESHOLD);
            keyGenerator.generateBatch(KgsConstants.BATCH_SIZE);
        }

        String key = redisTemplate.opsForList().rightPop(KgsConstants.REDIS_QUEUE_NAME);  // 原子出队
        if (key == null) {
            log.warn("Queue empty after refill (attempt {}/{})", attempt + 1, ...);
            continue;
        }

        // CAS：仅当 key 仍为 available 时才置为 used。
        // 若此前出现"标记超时但实际已成功"，key 已是 used → modifiedCount=0。
        // 不再 push 回队列：已 USED 的脏 key 若回队会陷入"取出→CAS 失败→回队"死循环，
        // 直接丢弃取下一个。
        var result = mongoTemplate.updateFirst(
                Query.query(Criteria.where("key").is(key).and("status").is(KgsConstants.STATUS_AVAILABLE)),
                Update.update("status", KgsConstants.STATUS_USED),
                "shortkeys"
        );

        if (result.getModifiedCount() > 0) {
            log.debug("Key issued: {}", key);
            return key;
        }
        log.warn("CAS failed for key {}, discarded (attempt {}/{})", key, attempt + 1, ...);
    }
    throw new RuntimeException("Failed to issue key after " + KgsConstants.MAX_ISSUE_ATTEMPTS + " attempts");
}
```

**关键点（面试核心）**：
- **为什么 RPOP + Mongo CAS 双保险？** RPOP 保证并发下不会两个消费者拿到同一个 key；Mongo CAS 保证**一个 key 全局只发放一次**（状态机 available→used）。两者防御的是不同层：Redis 防并发竞争，Mongo 防历史脏状态。
- **为什么 CAS 失败要"丢弃"而不是"回队"？** 注释写得很清楚：已 USED 的 key 回队会陷入"取出→CAS 失败→回队"死循环。丢弃的代价是少量 key 浪费（安全），回队的代价是无限循环（危险）。
- **惰性补货**：队列低于阈值 200 才同步补一批 1000，摊薄批量成本；发放路径本身 O(1) 无锁。

public class KeyGrpcService extends KeyServiceGrpc.KeyServiceImplBase {

    @Override
    public void getKey(Empty request, StreamObserver<KeyResponse> responseObserver) {
        try {
            String key = keyService.getKey();
            responseObserver.onNext(KeyResponse.newBuilder().setKey(key).build());
            responseObserver.onCompleted();
        } catch (Exception e) {
            responseObserver.onError(
                    Status.INTERNAL.withDescription("key generation failed: " + e.getMessage())
                            .asRuntimeException());
        }
    }

## 七、专题 A：二级缓存设计（缓存值携带 urlId）

### 7.1 缓存结构

```java
private static final String CACHE_PREFIX = "url:";
private static final Duration CACHE_TTL = Duration.ofHours(24);   // Redis L2 TTL
/** 缓存值分隔符："{urlId}|{originalUrl}"，携带 urlId 使缓存命中时无需回查 DB 即可记 analytics */
private static final String CACHE_SEPARATOR = "|";

private final Cache<String, String> localCache = Caffeine.newBuilder()
        .maximumSize(100_000)
        .expireAfterWrite(3, TimeUnit.SECONDS)                    // Caffeine L1 TTL
        .build();
```

**设计精髓**：Redis 值不是裸 URL，而是 `"{urlId}|{originalUrl}"`。跳转命中缓存时**同时拿到 urlId**，`analyticsAsyncService.record(urlId, ...)` 不需要再回查 DB 取 id——一次缓存读解决"跳转 + 统计定位"两件事。

### 7.2 读取与回填

```java
private CachedUrl getFromCache(String shortKey) {
    String local = localCache.getIfPresent(shortKey);             // L1
    if (local != null) return parseCached(local);

    String cached = redisTemplate.opsForValue().get(CACHE_PREFIX + shortKey);   // L2
    if (cached != null) {
        localCache.put(shortKey, cached);                          // L2 → 回填 L1
        return parseCached(cached);
    }
    return null;
}

/** 解析 "{urlId}|{originalUrl}"；无分隔符视为旧格式（id 缺失），损坏数据返回 null 回源 DB */
private CachedUrl parseCached(String value) {
    int idx = value.indexOf(CACHE_SEPARATOR);
    if (idx < 0) return new CachedUrl(null, value);
    try {
        return new CachedUrl(Long.parseLong(value.substring(0, idx)), value.substring(idx + 1));
    } catch (NumberFormatException e) {
        log.warn("缓存值格式异常，回源 DB 重新缓存: {}", value);
        return null;
    }
}

private void cacheUrl(Url url) {
    String value = url.getId() + CACHE_SEPARATOR + url.getOriginalUrl();
    localCache.put(url.getShortKey(), value);
    redisTemplate.opsForValue().set(CACHE_PREFIX + url.getShortKey(), value, CACHE_TTL);
}
```

**关键点**：
- **L1(Local) 3s / L2(Redis) 24h**：L1 拦截热点（同机重复请求），3s 短 TTL 保证最终一致性（DB 更新后最多 3s 内本地仍旧值，可接受）；L2 全局共享、长 TTL 兜底冷数据。
- **兼容性设计**：`parseCached` 兼容旧格式（无 urlId）——升级期间旧缓存不炸，只是不记统计，且损坏数据自动回源修复。
- 没有防击穿（DCL）——miss 直接回源 DB，这是本模块已知边界之一（见 §15）。

## 八、专题 B：限流体系（注解 + Lua 固定窗口）

### 8.1 Lua 脚本（原子 INCR + EXPIRE）

`vtsl-shortlink-api/.../ratelimit/RedisFixedWindowLimiter.java`：

```java
private static final String LUA =
        "local key = KEYS[1] " +
        "local limit = tonumber(ARGV[1]) " +
        "local window = tonumber(ARGV[2]) " +
        "local current = tonumber(redis.call('get', key) or '0') " +
        "if current >= limit then return 0 end " +
        "redis.call('incr', key) " +
        "if current == 0 then redis.call('expire', key, window) end " +
        "return 1";

public boolean tryAcquire(String key, int limit, int windowSeconds) {
    Long result = redisTemplate.execute(script, List.of(key),
            String.valueOf(limit), String.valueOf(windowSeconds));
    return result != null && result == 1L;
}
```

**固定窗口算法**：窗口内计数达到 limit 拒绝，`current == 0` 时设置过期（每个窗口第一条请求重置 TTL）。原子脚本保证并发安全。

### 8.2 拦截器（注解 → 执行）

`vtsl-shortlink-api/.../ratelimit/RateLimitInterceptor.java`：

```java
@Override
public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) {
    if (!(handler instanceof HandlerMethod hm)) return true;

    RateLimit rl = hm.getMethodAnnotation(RateLimit.class);        // 方法级注解
    if (rl == null) rl = hm.getBeanType().getAnnotation(RateLimit.class);   // 类级兜底
    if (rl == null) return true;

    String ip = getClientIp(request);
    String key = "rate_limit:" + ip + ":" + request.getRequestURI();   // IP + URI 双维度

    if (!limiter.tryAcquire(key, rl.limit(), rl.windowSeconds())) {
        response.setStatus(429);
        response.setContentType("application/json;charset=UTF-8");
        response.getWriter().write("{\"error\":\"Too Many Requests\"}");
        return false;
    }
    return true;
}
```

**关键点**：
- key = `rate_limit:{ip}:{URI}`——**同一 IP 的不同接口独立计数**（创建 5/min、跳转 50/min 互不干扰）；URI 含 path 变量，每个短码的跳转也独立限流。
- 注解式声明（`@RateLimit(limit = 5, windowSeconds = 60)`）让限流阈值与接口定义在一起，一目了然。

## 十、专题 D：存储选型分离（Mongo 账本 vs MySQL 业务表）

| 维度 | MongoDB（账本） | MySQL（业务） |
|---|---|---|
| 用途 | 短码全局唯一性：谁生成过、什么状态 | URL 映射：归属、点击、统计 |
| 表/集合 | `shortkeys`（key / status / createdAt） | `t_url` + `t_analytics` |
| 写模式 | 高频随机写（生成批插 + CAS 更新） | 低频业务写（CRUD + 统计 upsert） |
| 一致性手段 | `@Indexed(unique=true)` 唯一索引 + CAS 状态机 | `uk_short_key` 唯一索引 + 软删除 |
| 演进 | 只服务发号，无业务语义，可独立扩容 | 承载业务属性，事务/聚合友好 |

**为什么这样拆（面试话术）**：
- 发号器是**无状态高频写**：不关心 URL 属于谁，只关心"key 不重复"。Mongo 的文档模型 + 唯一索引天然适配，且与业务库解耦，避免发号写入挤占业务表。
- 业务映射是**低频但带语义**：需要事务（create 落库 + 缓存一致性）、聚合（点击统计）。MySQL 关系模型 + JPA 更合适。
- **短码字符串是唯一关联键**：两套存储之间没有外键，只通过 `short_key` 对齐——独立演进互不阻塞。

## 十三、链路关键点速查

| 关键点 | 一句话 |
|---|---|
| 生成/发放解耦 | 生成（随机 + Mongo 落账）批量做，发放（RPOP）O(1) 无锁 |
| 惰性补货 | 队列 < 200 → 批量补 1000；阈值/批量均可配置 |
| 防重双保险 | Redis RPOP 防并发竞争 + Mongo CAS(available→used) 防重复发放 |
| 脏 key 处理 | CAS 失败直接丢弃重取（最多 3 次），不回队避免死循环 |
| 随机短码 | SecureRandom + Base62 6 位 ≈568 亿容量，防枚举 |
| 缓存值携带 urlId | Redis 值 = `"{urlId}\|{originalUrl}"`，命中免回查 DB 即可记统计 |
| 缓存一致性 | Cache Aside：DB 先 → 删缓存；L1 3s 自然过期兜底最终一致 |
| 限流 | Lua INCR+EXPIRE 固定窗口，`rate_limit:{ip}:{URI}` 双维度 |
| 统计隔离 | @Async 线程池（CallerRunsPolicy）+ 异常吞掉，不阻塞主链路 |
| 存储分离 | Mongo 管唯一性（无业务语义），MySQL 管业务（事务/聚合），短码字符串解耦 |

## 十四、面试话术

> **Q: KGS 为什么用"预生成 + 队列"而不是直接每次现算？**
> 生成是重操作（SecureRandom 采样 + Mongo 落账），发放是轻操作（RPOP）。预生成把重操作批量摊销（一次 1000 个），发放路径只剩 O(1) 出队 + CAS，取号不成为创建链路瓶颈。惰性阈值（<200 补货）保证队列既不太空也不过度占用资源。

> **Q: 短码为什么用随机而不是自增/INCR？**
> 自增/INCR 短码可枚举——遍历短码就能抓取全量短链。SecureRandom 随机生成不可预测，防爬取；62⁶≈568 亿容量，碰撞概率极低，唯一索引兜底即可。

> **Q: 账本为什么用 MongoDB 不用 MySQL？**
> 发号是高频随机写、无业务语义，核心诉求只有"key 不重复"。Mongo 唯一索引天然防重、文档模型写放大低，且与业务库物理隔离，发号压力不挤占业务表；业务语义（归属、统计）留在 MySQL。

> **Q: CAS 失败怎么办？**
> 说明该 key 此前已被发放（状态已 used），直接丢弃取下一个，不回队——回队会让已 used 的 key 陷入"取出→CAS 失败→回队"死循环。最多重试 3 次，仍失败抛异常由 api 侧转 500。

> **Q: 缓存为什么带 urlId？**
> 缓存值设计成 `"{urlId}|{originalUrl}"`，跳转命中时 urlId 一并拿到，记点击统计不需要再回查 DB，一次缓存读解决两件事。

> **Q: 缓存一致性怎么保证？**
> Cache Aside：写操作先更新 DB 再删 Redis；L1 Caffeine 3s 短 TTL，DB 变更后最多 3s 内收敛。跳转读只走缓存 + DB 兜底，无脏写路径。

> **Q: 限流怎么做的？**
> Redis Lua 固定窗口（INCR+EXPIRE 原子），`@RateLimit` 注解声明阈值（创建 5/min/IP、跳转 50/min/IP），key 为 `rate_limit:{ip}:{URI}`，接口间独立计数。

> **Q: 点击统计为什么异步？**
> 跳转主链路只做缓存读 + 返回，统计（UPDATE clicks + GeoIP 远程调用 + INSERT 明细）全放 @Async 线程池；线程池 CallerRunsPolicy 反压 + 异常吞掉，统计失败/变慢都不影响跳转。

## 十五、已知边界（面试防御）

> 这些是当前实现的真实边界，面试被追问时有准备；也即代码后续演进方向。

1. **create 并发去重（TOCTOU）**：`existsByOriginalUrlAndUserId` 检查与 `save` 之间无唯一索引保护，极端并发下同 URL 可能建两条；`save` 撞 `uk_short_key` 的 `DuplicateKeyException` 未捕获会 500。→ 演进：捕获冲突转 409 / 加唯一约束。
2. **generateBatch 跨存储非原子**：Mongo insert 成功后 Redis push 失败 → 该批 available key 不进队列（账本与队列不一致）。→ 演进：push 失败重试。
3. **并发补货无锁**：多个并发 getKey 同时观察到队列 < 阈值会重复 generateBatch。→ 演进：refill 加 SETNX 锁。
4. **读链路无防击穿**：缓存 miss 直接回源 DB，热点短码失效瞬间可能有 N 个请求同时打 DB。→ 演进：DCL 分布式锁 + 自旋（弃案 simple 有实现可参考）。
5. **统计逐条写库**：每条点击一次 UPDATE + INSERT，日读百万量级会放大写放大；t_analytics 无分区/归档。→ 演进：Redis 聚合 + 定时批量刷盘，或 Kafka 批量消费。
6. **限流信任 XFF**：`getClientIp` 直接取 `X-Forwarded-For` 第一段，客户端可伪造绕过。→ 演进：只信任网关注入的 `X-Real-IP`。
7. **KGS 单点无降级**：KGS 不可用时 api 创建短链直接 500。→ 演进：本地随机生成 + 查重 fallback，或 gRPC 多实例负载均衡。
8. **缓存 TTL 固定 24h**：同时写入的短码会在 24h 后同批过期雪崩回源。→ 演进：TTL 加随机抖动（±10%）。
